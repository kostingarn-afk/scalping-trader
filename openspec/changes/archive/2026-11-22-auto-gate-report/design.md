# Design — auto-gate-report

## Context

См. `proposal.md` — Why. Критерий §1 — `to_do.md` §1; диагностика — `docs/mat_analyze.md` §5.
`report.py` уже знает `Trade` и `BacktestResult`; `statsmodels` и `scipy` в зависимостях.

## Goals / Non-Goals

**Goals:** вердикт §1 и диагностика в том же прогоне, без ручных скриптов.

**Non-Goals:** поправка на множественность (2.3), walk-forward-гейт (уже есть), JB в вердикте,
изменение порогов.

## Decisions

### D1. `gate = Σgross / Σcommission`

Так определён §1. Издержки исполнения (спред/импакт) в `gross` уже учтены: `gross` считается по
исполненным ценам, а комиссия — отдельно. Поэтому знаменатель — только комиссия: иначе `gate`
менял бы смысл при включении `--spread-bps`.

### D2. t-статистика по `net_pnl`

`t = mean / (std/√n)`, `ddof=1`. По сделкам, а не по дневным суммам: §1 говорит о t на
out-of-sample сделках; дневная агрегация теряет количество наблюдений.

### D3. OOS — последние 30 % по времени

Граница — `entry_ts_min + 0.7·(exit_ts_max − entry_ts_min)`; в OOS попадают сделки с
`exit_ts ≥ границы`. По времени, а не по счёту: иначе «out-of-sample» смещается к активным
периодам.

### D4. Тримминг — три лучших дня

Дневные `net` суммируются по дате выхода; вычитаются три наибольших значения. Прибыль после
удаления — сумма оставшихся дней. Это соответствует формулировке §1 «удаление 3 лучших
периодов» и не зависит от размера сделки.

### D5. Диагностика на дневных доходностях

`returns_d = daily_net / deposit`. ADF: `autolag="AIC"`; Ljung–Box: `acorr_ljungbox` с лагом
`min(10, n//2)`; JB: `jarque_bera`; эксцесс: `kurtosis(fisher=True)`. Меньше 8 дней или ряд
вырожден — `None`, в отчёте «—».

### D6. JB и гейт

JB не входит в вердикт: в скальпинге тяжёлые хвосты ожидаемы (эксцесс > 5). Печатается как
диагностика, чтобы видеть отклонение от нормальности, а не отбраковывать рабочие стратегии.

### D7. Вердикт — явный список провалов

`passed` = все четыре условия; `failed_checks` — человекочитаемые имена. Отчёт печатает
«пройден» или «не пройден: t OOS ≥ 2, ...» — по нему видно, что дорабатывать.

## Risks / Trade-offs

- **Мало OOS-сделок** → `t` не печатается, вердикт не пройден. Честнее, чем `t` по трём сделкам.
- **Дневная агрегация на короткой выгрузке** → диагностика «—»; это не провал, а нехватка данных.
- **`gate` без издержек исполнения** может быть оптимистичным → параметры исполнения печатаются
  в отчёте; при включённых издержках `gross` уже их содержит.
- **Тримминг по дням** может быть мягче, чем по «периодам стратегии»; порог §1 сформулирован в
  периодах, день — минимальная единица.

## Migration Plan
