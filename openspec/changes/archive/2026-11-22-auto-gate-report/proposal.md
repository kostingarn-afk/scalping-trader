# Proposal

## Why

Критерий приёмки §1 (`to_do.md` §1) — `gate ≥ 1`, `t ≥ 2` на out-of-sample, ≥ 50 сделок, прибыль
переживает удаление 3 лучших периодов. Сейчас отчёт печатает сделки, win rate, комиссию и PnL,
но не печатает ни `gate`, ни `t`, ни результат тримминга: решение «модель проходит гейт»
принимается вручную по таблице, а проверки стационарности и хвостов (`docs/mat_analyze.md` §5)
делаются отдельными скриптами или не делаются вовсе.

Шаг 1.8 требует, чтобы гейт считался в том же прогоне и печатался в отчёте — тогда кандидат
оценивается одной командой, а не набором ручных действий.

## What Changes

- **Модуль гейта** — `backtest/gate.py`: `gate = Σgross / Σcommission`, `t` по сделкам,
  out-of-sample `t` (последние 30 % периода), `Net без 3 лучших дней`, вердикт по четырём
  порогам §1.
- **Диагностика ряда** — ADF, Ljung–Box (лаг 10), Jarque–Bera и эксцесс по дневным доходностям
  (`net / депозит`); меньше 8 дней — «—», а не выдуманное значение.
- **Отчёт** — раздел «Гейт §1» в markdown: таблица по каждому прогону и явный вердикт с
  перечнем непройденных проверок.
- **Тесты** — пороги, тримминг, OOS-разбиение, диагностика на синтетике, наличие раздела в
  отчёте.

Не входит: поправка на множественное тестирование (шаг 2.3), walk-forward-гейт (уже есть в
`--walkforward`), переобучение модели, изменение порогов §1.

## Capabilities

### New Capabilities

- `backtest-validation`: автоматическая проверка результата прогона по критериям §1 и
  диагностика ряда в отчёте.

### Modified Capabilities

Нет.

## Impact

- Код: новый `analyzer/src/analyzer/backtest/gate.py`; правка `report.py` (раздел отчёта).
- Тесты: `analyzer/tests/test_gate.py`, дополнение `test_backtest_report.py`.
- Зависимости: `statsmodels` и `scipy` уже в проекте; новых нет.
- БД, Kafka, `proto/`, Trader — не затрагиваются.
