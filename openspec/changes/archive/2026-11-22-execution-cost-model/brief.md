# Brief — execution-cost-model

Шаг **1.6** плана `to_do.md` §4.1. Контекст: бэктест считает только комиссию, вход — по
открытию следующего бара, выход — по цене SL/TP. На минутном фрейме полуспред и импакт
сопоставимы с комиссией 0.05 %/сторона, поэтому `gate` завышен.

## Шаги

1. **Модель.** `backtest/execution.py`: `ExecutionModel(spread_bps, impact_bps_at_full,
   permanent_bps_at_full)`; поправка в б.п. = `spread + participation·(impact + 0.5·permanent)`;
   `participation = units/(объём бара × лот)`, потолок 1.0.
2. **Прогон.** `RunConfig.execution`; вход корректируется после сайзинга (нужно число единиц),
   выход — в `_close_trade` в сторону закрытия; `exit_price` сделки — исполненная цена.
3. **CLI.** `--spread-bps`, `--impact-bps`, `--permanent-bps`; дефолты 0.
4. **Отчёт.** Строка параметров называет издержки, когда они включены.
5. **Тесты.** Формула и потолок участия; прогон: цена входа выше/выхода ниже на ожидаемую
   величину; при нулевых параметрах результат совпадает с прежним.

## Принятые решения

- Коэффициенты в б.п. цены, а не в ₽ за единицу: сравнение инструментов с разной ценой становится
  осмысленным, калибровка — один параметр на эффект.
- Постоянный импакт входит с множителем 0.5: по AC средняя цена исполнения сдвигается на
  половину полного постоянного сдвига.
- Участие считается по объёму бара исполнения (для входа — бар `fill_index`), а не по среднему:
  импакт реален именно в момент исполнения.
- Сайзинг выполняется по цене до поправки, затем цена корректируется: итерация «размер ↔ цена»
  даёт доли процента, а цикл усложняет движок. Отклонение по риску меньше поправки исполнения.
- При нулевом объёме бара участие принимается за 100 % — консервативно и детерминированно.
- Нулевые параметры дают точное прежнее поведение: `price * (1 + 0) == price`.

## Отклонённые альтернативы

- **Квадратный корень из участия** (эмпирическая «square-root law») — не Almgren–Chriss; план
  называет AC, линейная модель и есть AC в дискретном виде.
- **Модель очереди и вероятности исполнения** — требует стакана в истории, которого нет.
- **Сдвиг всех будущих цен постоянным импактом** — в бэктесте нет книги заявок, чтобы отделить
  постоянную часть от временной; множитель 0.5 учитывает её в средней цене входа.
- **Учёт спреда и импакта в mark-to-market** — плавающий PnL считается по mid; издержки входят
  при исполнении, это и есть модель.

## Риски

- Оценка `gate` снизится: часть «прибыли» была неучтёнными издержками. Это ожидаемый и полезный
  эффект шага.
- Калибровки коэффициентов нет: дефолты 0, значения задаёт исследователь. Без калибровки вывод
  «модель убыточна» может быть слишком строгим — параметры печатаются в отчёте.
- Сайзинг по цене до поправки слегка завышает риск (на величину поправки). Зафиксировано.

## Способ проверки

- `pytest tests/test_execution.py` — 9 тестов: нулевая модель тождественна, спред сдвигает цену
  против стороны, импакт растёт с участием и упирается в 100 %, постоянный импакт идёт с
  множителем 0.5, нулевой объём трактуется как полное участие, валидация; прогон: вход дороже,
  выход дешевле, отчёт называет издержки.
- `pytest tests` — **315 passed**.
- `ruff check src tests` — All checks passed.
- Сравнение на реальных данных (AFLT 1min, 20 000 баров, OU, тариф `trader`):
  без издержек net −1 291 ₽, средняя сделка −92 ₽, t −0.65; со спредом 5 б.п. и импактом
  10 б.п. net −7 581 ₽, средняя сделка −542 ₽, t −3.79. Издержки исполнения меняют не только
  уровень, но и значимость — это и есть цель шага.

## Отклонения от плана

- Сайзинг считается по базовой цене, затем цена корректируется: итерация «размер ↔ цена» даёт
  доли процента, а цикл усложняет движок. Фактический риск выше расчётного на величину поправки.
- Постоянный импакт не сдвигает будущие цены (книги в бэктесте нет), а входит в среднюю цену с
  множителем 0.5 по AC.
