# Design — execution-cost-model

## Context

См. `proposal.md` — Why. Точки применения в движке: вход (`engine.py:207`,
`entry_price = bar.open` или `bar.close`) и выход (`_close_trade`, `exit_price` из SL/TP/таймаута).
Объём бара — `Bar.volume` в лотах, число единиц заявки — `lots × lot_size`.

## Goals / Non-Goals

**Goals:** спред и импакт в ценах исполнения, нулевое поведение по умолчанию, параметры в
отчёте.

**Non-Goals:** калибровка коэффициентов, стакан в истории, модель очереди, внутрибарная
траектория, лимитное котирование (3.6).

## Decisions

### D1. Линейная модель AC в б.п.

Итог: `cost_bps = spread + participation·(impact + 0.5·permanent)`,
`participation = min(units/(bar_volume·lot_size), 1)`.

AC в дискретном виде: временный импакт пропорционален скорости исполнения, постоянный —
половине полного сдвига в средней цене. В б.п. цены коэффициенты сравнимы между инструментами,
что важно для панели и смены списка.

*Альтернатива:* квадратный корень из участия — другая модель (эмпирическая), не AC.

### D2. Нулевые параметры — тождество

`price * (1 + 0) == price`; дефолты 0, поэтому существующие тесты и отчёты не меняются. Это
позволяет вводить модель без пересчёта всех прежних результатов.

### D3. Сайзинг до поправки

Размер позиции считается по базовой цене (риск = расстояние до SL), затем цена корректируется.
Итерировать «размер ↔ цена» дороже, чем ошибка в доли процента; фактический риск растёт на
величину поправки, что консервативно.

### D4. Участие по бару исполнения

Для входа — бар `fill_index` (где реально происходит сделка), для выхода — бар закрытия. Именно
в этот момент объём ограничивает исполнение.

### D5. Нулевой объём бара — участие 100 %

Делить на ноль нельзя, а оптимистично считать «участие 0» значит скрыть риск. Консервативно:
полный импакт.

### D6. `exit_price` — исполненная цена

Отчёт и `Trade` показывают фактическую цену выхода, а не теоретический уровень SL/TP: иначе
`gross` и `net` расходятся с колонкой цены.

## Risks / Trade-offs

- **Оценка стратегий ухудшится** → это и есть цель шага: `gate` честнее.
- **Нет калибровки** → значения задаёт исследователь; параметры печатаются в отчёте, чтобы
  прогоны не смешивались.
- **Постоянный импакт не влияет на будущие цены** → в бэктесте нет книги; учтён в средней цене
  входа с множителем 0.5.
- **Риск чуть выше расчётного** → сайзинг до поправки; поправка — доли процента от цены.

## Migration Plan

Аддитивно, дефолты нулевые. Откат — убрать поле `execution` и вызовы поправки.
