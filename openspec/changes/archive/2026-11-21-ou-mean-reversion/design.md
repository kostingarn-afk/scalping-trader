# Design — ou-mean-reversion

## Context

См. `proposal.md` — Why. Состояние после шага 1.1:

- `SignalModel` объявляет `fit(history)`, но `backtest/engine.py:197` вызывает только
  `strategy_fn(indicators, close, sl, tp)` — `fit` не вызывается ниоткуда;
- `backtest/models.py:111` задаёт `window = 200` для расчёта индикаторов; `RunConfig.window`
  меньше окна индикаторов быть не может;
- `backtest/cli.py:547` делает `replace(template, min_atr_pct=atr_threshold)` безусловно —
  конфиг без поля `min_atr_pct` упадёт с `TypeError`;
- `docs/mat_analyze.md` §2 задаёт формулы θ через ρ и правило half-life против горизонта.

## Goals / Non-Goals

**Goals:** модель `ou` в реестре, оценка параметров проверяемым способом, вызов `fit` в прогоне
без изменения поведения правил.

**Non-Goals:** Калман-фильтр, коинтеграция пар, тайминг входа по τ*, подбор порогов, EV-гейт 1.10.

## Decisions

### D1. AR(1) → OU через OLS, numpy без scipy

Модель `X_{t+1} = a + b·X_t + ε`. Оценки: `b = cov(x_t, x_{t+1}) / var(x_t)`,
`θ = −ln b`, `μ = a/(1−b)`, `σ_ε = RMS(остаток)`. Переход к непрерывным параметрам:
`σ = σ_ε·√(2θ/(1−b²))`, `σ_eq = σ/√(2θ)`.

*Почему не MLE по СДУ:* дискретизация ровно та же (точное решение OU на шаге Δt — AR(1)), а
формула θ через ρ в `docs/mat_analyze.md:54` — это и есть OLS-наклон. Отдельный оптимизатор не
нужен и не добавляет точности.

*Почему σ не по уровням:* стандартное отклонение уровней завышено трендом окна; остаток AR(1)
даёт вклад шума.

### D2. Отказ вместо фиктивных параметров

`estimate_ou` возвращает `None`, если `b ∉ (0,1)`, окно короче `min_bars`, есть нечисловые
значения или `σ_eq ≤ 0`. Модель на `None` отдаёт HOLD «параметры не оценены». Случайное
блуждание и тренд без возврата не должны превращаться в «средний уровень», иначе каждое
отклонение читается как возможность.

### D3. Half-life как фильтр применимости

`half_life = ln 2 / θ` в барах. Если больше `max_half_life_bars` (дефолт 10 — равен
`max_holding_time_minutes` из `risk_config`), модель отдаёт HOLD: возврат не успеет произойти за
горизонт удержания. Это ограничение этапа «низкочастотные модели не подменяют скальпинговую
логику».

### D4. `fit` перед `predict`, `warmup` — необязательный атрибут

`engine` вычисляет `lookback = max(cfg.window, getattr(model, "warmup", 0))`, передаёт
`bar_list[index+1−lookback : index+1]` в `fit`, затем считает индикаторы на прежнем окне
`cfg.window`. Разделение важно: длина среза индикаторов влияет на ATR/ADX (рекурсивные
сглаживания), и её изменение сдвинуло бы все действующие правила.

*Альтернатива:* передавать историю в `predict`. Отклонено: меняет `StrategyFn` и все места, где
он вызывается (`engine`, `nullmodel`, `walkforward`, `panel`).

### D5. Параметры модели — `--model-param key=value`

Флаг повторяемый, значения парсятся как int → float → str. `ou_config` валидирует имена и типы,
неизвестный ключ — ошибка. Так модель 1.3–1.5 добавляет параметры без правки парсера; в
walk-forward они уже варьируются через существующий `--wf-grid`.

### D6. Модель stateful, конфиг frozen

`OuMeanReversionModel` — обычный dataclass с полем `_params`; `fit` перезаписывает состояние.
CLI создаёт модель на каждый (датасет, интервал), поэтому состояние не переживает прогон; на
каждом баре `fit` вызывается до `predict` и состояние всегда актуально.

## Risks / Trade-offs

- **Шумная θ на коротком окне** → `min_bars` (30) и half-life фильтр; значения в конфиге.
- **Задержка сигнала** → z считается по μ, оценённому на том же окне, что и цена; это не
  look-ahead (только прошлые бары), но μ меняется от бара к бару — часть отклонения «съедается»
  переоценкой среднего. Замер на бэктесте, а не на глаз.
- **`σ_eq` мал** → z чувствителен; защита — ATR > 0 и комиссионный фильтр.
- **`--model-param` с неверным типом** → `window=240.5` даёт явную ошибку, а не тихое усечение.

## Migration Plan

Аддитивно: новая модель в реестре, вызов `fit` для моделей, у которых он есть. Откат — удалить
`ou.py`, запись реестра и вызов `fit`. Миграций нет.
