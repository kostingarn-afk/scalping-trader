# Proposal

## Why

Этап R0 дал входы: шаг цены, издержки круга `C` в тиках, `σ_τ` через `VR(τ)`, окна сессий.
Следующий шаг по §16 `buy_frame.md` — **фаза A** (заморозка политики до идентификации θ) и
**Gate 0a**: арифметическая проверка «хватает ли движения окупить издержки». Без неё
идентификация θ и EV(τ) считаются для геометрии, которая может быть заведомо убыточной.

`φ*(τ) = Cost / σ_τ`: если при всех τ значение больше единицы, издержки превышают типичное
движение на этом горизонте, и скальпинг невозможен никакой моделью (§7.1).

## What Changes

- **Политика фазы A** — один dataclass с параметрами (`q`, `α_total`, `λ`, `|Z_entry|`,
  `ρ_max`, `impact-бюджет`, `τ_cap`, `buffer`), значения по умолчанию из `to_do.md` §6.3,
  переопределение через YAML и переменные окружения. Невалидные значения отклоняются.
- **Заморозка** — `frozen_policy` и `policy_inputs`: барьеры `a, b` в тиках (объявляются как
  кратные `σ_1` и переводятся в тики по шагу цены), одна позиция, `κ`-кап, flat-at-close,
  список условий no-trade. Запись в `trial_registry` с id, ссылка из артефакта.
- **Gate 0a** — `phi_star_table`: `φ*(τ)` на τ ∈ {1, 3, 5, 10, 15, 30}, `σ_τ` в тиках,
  `Cost` в тиках; вердикт «проходит / арифметически невозможно» по каждому инструменту.
- **CLI** — подкоманда `phi-star` (`analyzer-research phi-star`), артефакты в `--out`.

Не входит: идентификация θ и Gate 1 (этап R2), EV(τ)/τ* (R3), Gate 0b (R4), runtime (R5).
