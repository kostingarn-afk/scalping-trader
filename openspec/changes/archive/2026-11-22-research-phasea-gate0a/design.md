# Design — research-phasea-gate0a

## 1. Политика как данные

`PolicyParams` — неизменяемый dataclass с полями из §6.3 `to_do.md`:

| Поле | Значение | Смысл |
|---|---|---|
| `q` | 0.10 | допустимая вероятность смены режима до выхода |
| `alpha_total` | 0.05 | уровень онлайн-теста валидности (`α_check = α_total/n_checks`) |
| `z_entry` | 2.0 | порог входа `|Z_entry|`, объявлен, не оптимизируется |
| `rho_max` | 0.25 | доля объёма бара для выхода |
| `impact_budget` | 0.25 | доля ожидаемого edge под влияние на цену |
| `tau_cap_minutes` | 60 | предел скальпинга (`SCOPE_VIOLATION` при `τ* > τ_cap`) |
| `buffer_minutes` | 5 | запас до flat-at-close |

`λ` не хранится отдельным полем: `λ = z_entry/(2√2)` — производная величина, чтобы нельзя было
задать два противоречащих значения. Свойство `lambda_risk` вычисляет её и проверяет, что
`z_entry` положителен.

Валидация на уровне `__post_init__`: диапазоны (`0 < q < 1`, `0 < α < 1`, `z_entry > 0`,
`0 < ρ_max ≤ 1`, `0 ≤ impact_budget < 1`, `τ_cap ≥ 1`, `buffer ≥ 0`). Ошибка, а не «поправим
потом»: эти числа входят в статистику и в гейты.

Загрузка: `PolicyParams.from_mapping(payload)` для YAML и `PolicyParams.from_env(environ)` для
переменных (`RESEARCH_Q`, `RESEARCH_ALPHA_TOTAL`, …). Приоритет: аргумент CLI → env → YAML →
значения по умолчанию. Реализуется `load_policy(yaml_path=None, environ=None)`.

## 2. Барьеры и заморозка

Барьеры задаются в единицах `σ_1`: `a = k_a·σ_1`, `b = k_b·σ_1`, `k_a = 2.0`, `k_b = 1.5`,
округляются до целого числа тиков (половина вверх). Причина: абсолютные тики несравнимы между
инструментами, а проценты от цены возвращают ошибку единиц, от которой уходили в R0.

`FrozenPolicy` фиксирует: параметры, `k_a/k_b`, `|Z_entry|`, сайзинг (одна позиция, объём —
через `ρ_max`), `κ`-кап (одна позиция на инструмент), flat-at-close (`buffer`), список условий
no-trade. `freeze()` возвращает артефакт `frozen_policy` и запись в `TrialRegistry`; id записи
обязателен в артефакте (`policy_inputs.registry_id`).

`anchor_freeze_log` — список `μ` (якорь) по инструментам с временем фиксации: якорь нельзя
сдвигать задним числом, иначе EV(τ) перестаёт быть воспроизводимым.

## 3. Gate 0a

```
σ_τ^ticks = σ_1^log · √(τ · VR(τ)) · price / tick
φ*(τ)     = Cost^ticks / σ_τ^ticks
```

- `σ_1^log` — Parkinson (из R0), `price` — последнее закрытие, `tick` — шаг цены инструмента.
- `Cost` — круг из `costs.py`; рядом печатается стресс-вариант ×1.5.
- `φ*` считается на сетке τ = {1, 3, 5, 10, 15, 30}. `VR` берётся из десезонализованных
  доходностей; для τ, где данных не хватает, строка помечается `NO_DATA`, а не пропускается
  молча.
- Вердикт: `PASS`, если `min φ* < 1`; иначе `IMPOSSIBLE` для инструмента. Если `IMPOSSIBLE`
  у всех инструментов — Gate 0a провален, исследование останавливается (§7.1).

`φ*` не зависит от барьеров и от θ, поэтому Gate 0a выполняется сразу после фазы A и до
идентификации θ — как требует §16.

## 4. Артефакты и CLI

`phi_star_table` — конверт `build_artifact`: `units` (`cost: ticks`, `sigma_tau: ticks`,
`phi_star: ratio`), `n` (число инструментов), `method` («σ_1 Parkinson, VR по неперекрывающимся
окнам, Cost = 2×комиссия + спред»), `flags` (`tick: UNVERIFIED`, `spread: UNVERIFIED`),
`payload` со строками по инструментам и τ.

CLI: `analyzer-research phi-star --data-dir … --out … [--tariffs trader] [--spread-bps 5]
[--policy path.yaml] [--stress]`. Код возврата: `0` — Gate 0a пройден хотя бы одним инструментом,
`1` — провал у всех, `2` — ошибка ввода. Флаг `--tariffs` сохраняется как в `analyzer-backtest`
для совместимости команд.

## 5. Границы

θ, `σ_P`, EV(τ), τ*, правило удержания и runtime — следующие этапы. `policy.py` проектируется
так, что `FrozenPolicy` уже содержит всё, что понадобится R3 (барьеры в тиках, `τ_cap`,
`buffer`, `λ`), и его не придётся расширять при переходе.
