# Design — hawkes-clustering

## Context

См. `proposal.md` — Why. Состояние после 1.3: `MicrostructureState` копит стакан и объёмы
сделок (без времён), `Indicators` знает `vpin` и `order_imbalance`; trades приходят в handler
с `ts` из `RawMarketData`.

## Goals / Non-Goals

**Goals:** оценка branching ratio, проверяемая на синтетике; индикатор `hawkes` в
production-пути; модель-фильтр.

**Non-Goals:** Jump-diffusion (размер и частота скачков), переключение на momentum,
онлайн-обновление оценки (рекурсивная MLE), Avellaneda–Stoikov.

## Decisions

### D1. Экспоненциальное ядро и MLE

`λ(t) = μ + Σ α·e^{−β(t−t_i)}`, `n = α/β`. Лог-правдоподобие считается рекуррентно:
`S_i = e^{−βΔt}(1 + S_{i−1})`, компенсатор `μT + n·Σ(1 − e^{−β(T−t_i)})`.
Оптимизация — `scipy.optimize.minimize(L-BFGS-B)` по `log μ`, `logit n`, `log β`: `n` не
выходит из (0,1) по построению, ограничения не нужны.

*Альтернатива:* оценка по бинам/ACF — дешевле, но даёт не branching ratio, а эвристику.

### D2. Симуляция — thinning Огаты

Кандидат из `Exp(λ(t))`, приём с вероятностью `λ(t+Δt)/λ(t)` (интенсивность между событиями
только убывает). `n=0` даёт пуассоновский поток — база для теста «оценка различает режимы».

### D3. Оценка с прореживанием

MLE в Python-цикле на 500 событий — единицы миллисекунд, на каждой сделке это лишняя нагрузка.
`hawkes_refresh` (25) — пересчёт не чаще; `hawkes_window` (500) — окно времён. Оценка считается
в `MicrostructureState` и кэшируется до следующего refresh.

### D4. `min_events = 50`

Меньше — MLE нестабильна; индикатор пуст, модель молчит. Константа модуля, а не параметр: это
свойство оценки, а не торговой логики.

### D5. Модель фильтрует, а не переключает

При `n ≥ порога` модель отдаёт HOLD, а не входит по momentum: направление лавины (продолжение
или разворот) из интенсивности не следует. Переключение направления — отдельная гипотеза с
собственным гейтом.

### D6. Времена сделок — из protobuf

Handler передаёт `ts` сообщения (`seconds + nanos/1e9`). Если `ts` отсутствует, сделка
учитывается в VPIN, но не в Hawkes: подставлять время получения бессмысленно — это часы
потребителя, а не биржи.

## Risks / Trade-offs

- **Потерянные сделки** → `n` занижается (поток выглядит ровнее). Компенсация: сравнение с VPIN,
  наблюдение в production.
- **Стоимость MLE** → прореживание; при необходимости увеличивают `hawkes_refresh`.
- **Локальный оптимум** → три параметра, разумная инициализация (`rate/2`, `n=0.3`, `β=1/средний
  интервал`); тест на двух режимах.
- **Бэктест без сделок** → модель всегда HOLD; зафиксировано в README.

## Migration Plan

Аддитивно. Откат — убрать модель, индикатор и буфер времён. Миграций нет.
