# Proposal

## Why

Три правила входа (`mean_reversion`, `momentum`, `v2`) — разрозненные функции с разными
подписями и тремя отдельными frozen-конфигами. Общего интерфейса нет, поэтому каждая новая
модель из `to_do.md` §4.1 (шаги 1.2–1.5: OU, микроструктура, HMM, Hawkes) требует правки
реестра CLI в трёх местах: `choices`, `_strategy_config`, `_builder_for`. Последний молча
уводит неизвестный конфиг в `momentum` (`backtest/cli.py:552-556`), то есть новая модель может
считаться чужой стратегией без ошибки.

Статистическим моделям нужны `fit` и `params` (оценка параметров на train-части, purge/embargo
из `docs/monitoring.md` §3), которых текущая схема «функция + конфиг» не выражает. Без единого
протокола шаг 1.8 (автоматический гейт) не сможет одинаково опрашивать модели, а шаг 1.1 плана
останется формальностью.

## What Changes

- **Analyzer: протокол `SignalModel`** — `name`, `version`, `params()`, `fit(history)`,
  `predict(indicators, price, *, atr_mult_sl, atr_mult_tp)`. Структурный `BarLike` для `fit`
  объявлен в том же пакете, чтобы не тянуть зависимость на `backtest.models` (иначе цикл
  `signal_models ↔ backtest`).
- **Analyzer: адаптеры трёх действующих правил** — `MeanReversionModel`, `MomentumModel`,
  `MeanReversionV2Model` делегируют в существующие функции без изменения поведения; `fit` —
  явный no-op, `params()` отдаёт значения конфига.
- **Analyzer: единый реестр** — `MODEL_FACTORIES` и `build_model(name, **params)`; неизвестное
  имя даёт исключение, а не подстановку `momentum`. `--strategy` в CLI строится из реестра.
- **Тесты: golden-паритет** — на фиксированном ряду `predict` каждого адаптера совпадает с
  вызовом исходной функции до последнего поля `Signal`.
- Production-путь Analyzer (`main.py`, `strategy.mean_reversion`) не меняется: включение модели
  в live — отдельный шаг после гейта §1 (`to_do.md` §4.1, ограничения этапа).

Не входит в объём: статистические модели 1.2–1.5, EV-гейт 1.9/1.10, правка тарифа.

## Capabilities

### New Capabilities

- `signal-modeling`: единый контракт модели сигнала (протокол, реестр, конфиг) и правила
  подключения новых моделей к бэктесту без правки точки вызова.

### Modified Capabilities

Нет. Требования `signal-analysis` (расчёт индикаторов, генерация и публикация сигналов) не
меняются: протокол вводится над существующими правилами, а production-путь остаётся прежним.

## Impact

- Код: новый пакет `analyzer/src/analyzer/signal_models/`, правка
  `analyzer/src/analyzer/backtest/cli.py` (реестр вместо трёх мест), тесты
  `analyzer/tests/test_signal_models.py`.
- Конфигурация и зависимости: без изменений; новых внешних пакетов нет.
- БД, Kafka, `proto/`, Flyway-миграции — не затрагиваются.
- Документация: раздел в `analyzer/README.md` о расширении набора моделей.
