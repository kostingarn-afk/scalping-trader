# Brief — signal-model-protocol

Шаг **1.1** плана `to_do.md` §4.1. Контекст: набор моделей Analyzer расширяется (1.2–1.5), а
точка подключения модели размазана по трём местам CLI и молча подставляет `momentum` на
неизвестном конфиге (`backtest/cli.py:552-556`). Статистическим моделям нужны `fit`/`params`,
которых текущая схема «функция + frozen-конфиг» не выражает.

## Шаги

1. **Протокол.** В `analyzer/src/analyzer/signal_models/` объявить контракт модели: имя, версия,
   параметры, обучение на истории, предсказание по индикаторам и цене. `BarLike` — структурный
   тип истории, чтобы не зависеть от `backtest.models` (иначе цикл импортов).
2. **Адаптеры.** Три действующих правила (`mean_reversion`, `momentum`, `v2`) обернуть в
   адаптеры, делегирующие в существующие функции. Поведение не меняется: `fit` — явный no-op,
   `params()` отдаёт значения конфига.
3. **Реестр.** Единый `MODEL_FACTORIES` + `build_model(name, **params)`; неизвестное имя —
   ошибка. `--strategy` в CLI строится из реестра, `_strategy_config`/`_builder_for` убираются
   как отдельный источник истины.
4. **Golden-тесты.** На фиксированном ряду сигнал адаптера совпадает с исходной функцией по всем
   полям `Signal`; реестр отдаёт все три имени; неизвестное имя даёт исключение.
5. **Документация.** Раздел `analyzer/README.md`: как добавить модель, не правя точку вызова.

## Принятые решения

- Протокол — структурный (`typing.Protocol`), не базовый класс: существующие функции остаются
  вызываемыми напрямую, адаптер не наследует продовый код.
- `fit` в контракте обязателен даже для правил без параметров: иначе статистическая модель и
  правило окажутся в разных типах и гейт 1.8 не сможет опрашивать их единообразно.
- Единица выбора — имя модели + параметры; реестр — единственный источник списка.
- Production-путь (`main.py`) не переключается: ограничение этапа (`to_do.md` §4.1).

## Отклонённые альтернативы

- **ABC/базовый класс** — заставляет править существующие функции и создаёт ромбовидное
  наследование при появлении статистических моделей.
- **Оставить `_builder_for` с fallback** — дефект сохраняется: новая модель молча считается
  momentum.
- **Перенести `Bar` в общий модуль** — шире диффа; структурный `BarLike` решает ту же задачу без
  перемещения типов и без риска для `backtest`.
- **Сразу переключить production на реестр** — нарушает ограничение этапа до гейта §1.

## Риски

- Golden-тест на фиксированном ряду ловит изменение поведения, но не доказывает отсутствие
  зависимости от данных: при смене ta-lib значения индикаторов сдвинутся и тест обновится вместе
  с ними. Компенсация: сравнение идёт «адаптер против исходной функции» в одном прогоне.
- Реестр и `--strategy` могут разойтись, если где-то останется ручной список. Компенсация:
  `choices` в CLI вычисляется из реестра, тест сверяет состав.
- `params()` может протащить в отчёт несериализуемые значения. Компенсация: контракт требует
  примитивов, тест проверяет JSON-сериализуемость.

## Отклонения от плана

- `brief.md` создан после `proposal.md` (нарушен порядок «до первой правки артефактов»);
  содержимое соответствует фактическому состоянию артефактов на момент создания.
- Реестр реализован как `ModelSpec` (конфиг-класс, фабрика, разбор флагов, метка варианта).
  Разбор флагов лежит рядом с моделью в `builtin.py`, а не в CLI: иначе добавление модели
  снова требовало бы правки точки вызова — это и был дефект `_builder_for`.
- `predict` принимает множители ATR из прогона (`RunConfig`), а не хранит их в модели: иначе
  появился бы второй источник истины для `--atr-sl/--atr-tp` и `--tp-sl`.
