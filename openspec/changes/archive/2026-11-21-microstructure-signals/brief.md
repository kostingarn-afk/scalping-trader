# Brief — microstructure-signals

Шаг **1.3** плана `to_do.md` §4.1. Контекст: Collector публикует `ORDER_BOOK` и `TRADE` в
`raw-market-data`, Analyzer разбирает только свечи — стакан и поток сделок теряются, поэтому
`order_imbalance` в production всегда `None`, а модели микроструктуры питать нечем.

## Шаги

1. **Разбор сообщений.** `parse_message` возвращает свечу, стакан или сделку; `parse_candle`
   остаётся обёрткой (совместимость с существующими тестами и вызовами).
2. **Состояние.** `microstructure.py`: последний стакан по figi, поток сделок с направлением
   (из сообщения, иначе тик-правило), объёмные бакеты и VPIN.
3. **Индикаторы.** `Indicators.vpin`; `compute_all(..., vpin=...)`; `order_imbalance` считается
   из стакана, переданного handler'ом.
4. **Production-путь.** `main.process` передаёт стакан и VPIN в расчёт; `analysis_results`
   получает `order_imbalance` и `vpin` (стратегия остаётся `mean_reversion`).
5. **Модель.** `microstructure` в реестре: направление по OBI, фильтр токсичности по VPIN,
   HOLD без данных; параметры через `--model-param`.
6. **Тесты.** Тик-правило, бакеты/VPIN (односторонний → 1, сбалансированный → 0, мало данных →
   None), состояние стакана, сигналы модели, пас VPIN в `Indicators`.

## Принятые решения

- VPIN — бакеты фиксированного объёма, а не времени: метрика измеряет дисбаланс информированного
  потока, поэтому окно должно быть объёмным (`docs/mat_analyze.md` §1 — обоснование потока).
- Неизвестное направление сделки не угадывается: при отсутствии предыдущей цены сделка в бакеты
  не идёт, при равенстве цен — наследует предыдущее направление.
- VPIN возвращает `None`, пока не набрано `vpin_buckets` завершённых бакетов: частичное окно
  смещает оценку.
- Модель не подменяет production: включение в live — отдельный шаг после гейта.
- Стакан в бэктесте отсутствует: модель `microstructure` в прогоне на CSV всегда HOLD; это
  ограничение данных, а не поведения, и оно фиксируется в README.

## Отклонённые альтернативы

- **VPIN по времени (окно N минут)** — смешивает кластеризацию объёма с дисбалансом; бакеты по
  объёму и есть стандартное определение.
- **Классификация сделок по цене относительно середины стакана** — требует синхронного стакана на
  каждую сделку; тик-правило проще и не зависит от задержки стакана.
- **Новый топик для микроструктуры** — Collector уже публикует всё в `raw-market-data`; менять
  контракт незачем.
- **Отдельный процесс для VPIN** — расчёт O(1) на сообщение, отдельный конвейер не оправдан.

## Риски

- Стакан приходит чаще свечей: handler обрабатывает больше сообщений. Компенсация: обновление
  состояния O(depth), без numpy на каждое сообщение.
- Направление `UNSPECIFIED` у части сделок уменьшает выборку бакетов — VPIN позже становится
  доступен. Компенсация: тик-правило и конфигурируемый размер бакета.
- VPIN и OBI — новые ключи в JSONB; потребители (`analysis_results`) читают JSON целиком, схема
  не фиксирует набор ключей.
- Модель `microstructure` в бэктесте даёт 0 сделок; это может выглядеть как «сломанная» модель.
  Компенсация: явное предупреждение в README и в причине HOLD.

## Способ проверки

- `pytest tests/test_microstructure.py` — тик-правило, бакеты VPIN (односторонний → 1,
  сбалансированный → 0, перенос объёма, неизвестное направление), снимок состояния, четыре
  сценария модели, конфиг.
- `pytest tests --ignore=tests/test_handler.py --ignore=tests/test_signal_publisher.py` —
  276 passed, 1 skipped: тест production-пайплайна (`order_imbalance` и `vpin` в записи БД)
  пропускается без пакета `kafka` в venv, как и два файла на `*_pb2.py`; при полном окружении
  он выполняется.
- `ruff check src tests` — All checks passed.
- `analyzer-backtest --strategy microstructure --model-param obi_entry=0.3` на
  `data/history-1min` — отчёт строится, метка `micro-0.3-0.5`, 0 сделок на всех инструментах:
  в CSV нет стакана, модель молчит, как и заявлено.
- Разбор `ORDER_BOOK`/`TRADE` protobuf не покрыт автотестом: `tests/test_handler.py` не
  запускается без сгенерированных `*_pb2.py`. Проверка ветки — владельцем на production-пути
  (запуск Collector и проверка `order_imbalance`/`vpin` в `analysis_results`).
