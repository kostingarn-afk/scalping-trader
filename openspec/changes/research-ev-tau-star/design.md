# Design — research-ev-tau-star

## 1. Первое касание, `EV(τ)`, `V(τ)`

Исход в тиках (`holding_exiting.md` §4):
`X(τ) = a·1_TP − b·1_SL + ΔP_τ·1_N`, `EV(τ) = E[X] − C`, `V(τ) = Var(X)`.

Протокол — **эмпирический по 1m, конвенция «SL первым»**:

1. Для каждого сигнального бара (вход по `s = ±1`) строятся пути длиной `τ` внутри торгового окна.
2. Барьер TP = `a` тиков, SL = `b` тиков от цены входа; барьеры в тиках, не в процентах.
3. Если в одном баре задеваются оба барьера — считается SL (конвенция смещает EV вниз).
4. Если барьеры не задеты за `τ` — исход `N` с `ΔP_τ` по close бара `t+τ`.
5. Пути, у которых окно кончается раньше `τ`, отбрасываются (`NO_DATA`), а не укорачиваются:
   усечение смещает `p_N` и `EV`.

`p_TP, p_SL, p_N` — частоты трёх исходов; `EV` — их средневзвешенный исход минус `C`
(круг из `costs.estimate_cost`). `EV_LCB` — сдвиг на нижнюю границу блочного bootstrap.

CI: **кластерный bootstrap по торговым окнам** (кластер = окно; `B = 200` ресамплов, сид
фиксирован). Блочный bootstrap по подряд идущим сигналам неприменим: сигналы разрежены, и блок
«`2τ` подряд идущих входов» почти никогда не набирается — интервал выродился бы в точечную
оценку молча. Требование блока ≥ `2τ` сохраняется как проверка: если окно короче `2τ` баров,
точка получает статус `CI_DEGENERATE` и перестаёт быть основанием для входа. Newey–West не
реализуется: при перекрывающихся путях HAC требует выбора лага, который пришлось бы подбирать
по данным.

Численная краевая задача (§4, второй протокол) реализуется как `REFERENCE_ONLY`-сверка на
синтетике: она проверяет эмпирику там, где истина известна, но в операционные артефакты не идёт.

## 2. Горизонт: `w`, `τ*`, сигнальный ряд и граница геометрии

`w` — среднее ожидание следующего сигнала в барах на замороженной политике:
`w = (число баров между входами)`, оценка по train, с флагом `ENDOGENOUS: порог входа влияет на w`.

Объектив: `τ* = argmax_τ EV(τ)/√(V(τ)(τ+w))`. Альтернатива `EV/(τ+w)` — `REFERENCE_ONLY`,
не выбирается (объявить один вариант — §5).

`τ*` ищется на train с фиксированной сеткой τ **на множестве `τ ≤ τ_cap`**. Если максимум
объектива достигается при `τ > τ_cap`, это `SCOPE_VIOLATION`, а не «взять лучший из допустимых»:
подмена горизонта внутри допустимого множества была бы выбором под данные. Если максимум лежит
на правом краю сетки, это `BOUNDARY` (сетка коротка). Горизонт входа — сам `τ*`; вход разрешает
`EV_LCB(τ*) > 0` и `τ* ≤ τ_max`.

**Сигнальный ряд — провизионный.** Тиков нет, поэтому якорь `μ` — накопленный VWAP окна
(только прошлые и текущий бар), `Z = (P − μ)/σ_P`, вход против отклонения при `|Z| ≥ |Z_entry|`.
Метка `PROVISIONAL_SIGNAL` / `UNVERIFIED:signal-series` наследуется из R0: полноценная сигнальная
модель — R5, и при её изменении EV-кривая пересчитывается целиком.

**Граница геометрии (§3 `holding_exiting.md`).** `EV ≤ a − Cost` при любых вероятностях, поэтому
`a ≤ Cost` исключает положительный EV. Проверка печатается как `sanity.max_ev_upper_bound` и
флаг `NEGATIVE_BOUND`; это не гейт, а объяснение вердикта. На отчётном окне она срабатывает:
при `k_tp = 2` барьер `a = 2σ_1`, а круговые издержки у MTSS и T — `2.4σ_1` и `≈2σ_1`.
Менять `k_tp`/`k_sl` здесь нельзя: политика фазы A заморожена, вопрос выносится как решение
владельца.

## 3. Верхние границы `τ_max`

`τ_max = min(τ_edge, τ_regime, τ_mtf, τ_model, τ_liq, τ_session, τ_cap)`, формулы — §6.

- `τ_edge = max{τ: EV_LCB(τ) > 0}`; отсутствие такого τ — «нет сделки».
- `τ_regime = Δ_HTF·⌊ln((1−q)/γ_t(fav)) / ln P̂_LCB(fav,fav)⌋`.
- `τ_mtf` — консервативный минимум из `τ_regime` и оценки выживания на 10m при расхождении
  состояний 10m/15m; расхождение трактуется как «режим под вопросом» и укорачивает горизонт.
- `τ_model` — горизонт инвариантности `θ̂` из R2 (30 мин на базовой сетке, 60 при эскалации).
- `τ_liq = Δt·⌈Q/(ρ_max·V_1m)⌉`; мягкая: немедленный выход с impact по `Y·σ_h·√(Q/V_h)`.
- `τ_session = T_close − t − max(τ_liq, Δt) − buffer` (из `sessions.tau_session`).
- `τ_cap` — из политики (60).

Округление: `τ_edge`/`τ_regime`/`τ_liq` — вверх, `τ_max` — вниз, кратно Δt. Компонент, который
не идентифицирован, помечается `REFERENCE_ONLY` и не подменяется единицей: `τ_max` считается по
остальным, а причина пишется в `tau_max_components`.

Блокирующий гейт: `γ_t(fav) < 1−q` → вход запрещён независимо от сигнала.

## 4. Режим: HMM-15m и Gate 2

Признаки бара 15m: доходность, range-based волатильность, дисбаланс объёма. `K = 2`
(спокойный/волатильный), гауссовы эмиссии с диагональной ковариацией (`hmmlearn.GaussianHMM`),
сид фиксирован, несколько рестартов — берётся лучший likelihood.

Gate 2: `N_trans ≥ 10·K·(K−1)` — минимум 20 переходов для `K = 2`. При провале:
`γ_t` и `τ_regime` уходят в `REFERENCE_ONLY`, `τ_max` считается по остальным компонентам,
а отчёт несёт `GATE2_FAILED`; понижение `K` или приор — только как отдельное решение,
не автоматически.

Состояния упорядочиваются по волатильности (детерминированно, без подгонки под результат).
`fav` — состояние, благоприятное для позиции, определяется знаком `s` и знаком дрейфа состояния.

Выживание 10m: та же матрица переходов применяется к 10m-барам; расхождение состояний
15m/10m на одном отрезке даёт `τ_mtf` и запись `mtf_confirmation` (`DIAGNOSTIC` до подтверждения
в R4).

## 5. Удержание

`Hold ⇔ m_rem − λ·s_rem > E[C_later] − C_now`, где `m_rem, s_rem` — условные среднее и СКО
остаточного движения при тех же барьерах, тем же протоколом §1 из текущего состояния
(`A_t`, `τ_rem`). `A_t ≤ 0` — выход (overshoot). Продление в MR-режиме запрещено: при `A_t ≤ 0`
остаточный edge против позиции. Трейлинг недоступен (momentum-режим не идентифицирован).

Безбарьерная форма (порог `λ√(2·coth(θτ_rem/2))`) — `REFERENCE_ONLY`, в решение не входит.

## 6. Онлайн-тест валидности

На сигнальном ряде, в координате `A`:
`A_t | A_0 ~ N(A_0·e^{−θt}, 1 − e^{−2θt})`.
Консервативная нижняя полоса:
`A_0^LCB·e^{−θ_LCB·t} − z_{1−α_check}·√(1 − e^{−2θ_UCB·t})`,
`α_check = α_total / n_checks`, `n_checks = τ_max/Δt`. `A_0^LCB` использует нижние границы
`θ` и `σ_P` из R2. Пробой полосы — выход по политике (жёсткий триггер), это тест модели,
а не стоп-лосс.

## 7. Таблица выходов и исполнение

11 триггеров §9 с типом: жёсткий (TP/SL, time stop, model invalid, regime breaker,
regime confidence, session), редукция (`Regime confirmation 10m`, `Vol spike`), штатный
(anchor/edge, overshoot), «по §7» (close-cost drift). Каждый закрывающий триггер пишется
в `trade_log` как причина выхода; каждый триггер-редукция — ещё и в `no_trade_reports`.

Офлайн-исполнение (бар за баром):
1. Проверить гейты входа: `τ_max`, `γ_t(fav) ≥ 1−q`, существование `τ` с `EV_LCB > 0`,
   sanity `D > C`.
2. Открыть позицию по close бара сигнала (без look-ahead).
3. На каждом баре: порядок проверок — SL, TP, time stop, model invalid, regime, session.
4. Записать исход: `net` в тиках (после `C`), причина выхода, `τ` факт, `A_t` на выходе.
5. Нет сделки — запись в `no_trade_reports` с причиной (`SCOPE_VIOLATION`, `GATE`, `NO_TAU`,
   `SANITY`), без ослабления порогов.

`D = A_0·σ_P` в тиках; `σ_P` переводится из лог-шкалы R2 через цену входа и шаг цены.

## 8. Артефакты и CLI

Артефакты (конверт `build_artifact`, единицы из закрытого списка):
`first_passage-protocol.json` (`first_passage_protocol`), `ev-curve.json` (`ev_curve`),
`tau-star.json` (`tau_star_selection`), затем `tau_max_components`, `hmm_fit`,
`regime_survival`, `regime_survival_10m`, `hold_rule_config`, `online_band_spec`,
`exit_trigger_table`, `trade_log`, `no_trade_reports`.

Единицы, добавленные в закрытый список под R3: `ticks^2` (дисперсия исхода),
`ticks/sqrt(min)` (диффузионная σ в тиках), `min^-1/2` (объектив `τ*`
`EV/√(V·(τ+w))`). Без них артефакт пришлось бы помечать чужой единицей.

CLI: `analyzer-research ev --data-dir … --out … [--theta-dir …] [--weeks 4–8|0]
[--taus …] [--bootstrap …] [--policy yaml]`; `theta`/σ/σ_P читаются из артефактов Gate 1
(`--theta-dir`, по умолчанию каталог `--out`) — без них подкоманда возвращает код 2, а не
пересчитывает θ по другому окну молча. Коды возврата: 0 — есть вход, 1 — вердикт без входа,
2 — ошибка ввода.

## 9. Границы

Gate 0b, CPCV, DSR/FDR (R4) не входят; `trade_log` — вход для них. Runtime (R5) не входит:
`policy_exec` — офлайн-цикл над историей, не торговый контур.
