# Design — research-gate0-baseline

Решения этапа R0 (`to_do.md` §5). Спека — `specs/research-validation/spec.md`; обоснование
границ изменения — `brief.md`.

## 1. Пакет `analyzer.research`

Отдельный пакет, не импортирует production-модули (`consumer`, `strategy`, `indicators`) и не
тянет Kafka/asyncpg: этап R0 — офлайн-анализ выгрузок. Обратная зависимость допустима:
`backtest.loader` отдаёт метаданные, `research.ticks` из них строит шаг цены.

| Модуль | Ответственность | Не делает |
|---|---|---|
| `units.py` | `Parameter`, реестр, проверка единиц | не считает метрики |
| `ticks.py` | шаг цены, перевод цен и дельт в тики | не читает файлы (принимает цены/метаданные) |
| `sessions.py` | расписание, `τ_session`, `T_close` | не фильтрует бары (это делает вызывающий) |
| `integrity.py` | Gate D, уровни замечаний | не останавливает процесс сам — возвращает отчёт |
| `variance.py` | Parkinson/GK/RS, `VR(τ)`, `σ_τ` | не строит барьеры и не гейтует |
| `costs.py` | круг в тиках, стресс ×1.5 | не решает, «выгодно ли» |
| `labels.py` | вариант метки, `h_max` | не строит фичи |
| `registry.py` | `trial_registry` | не считает DSR |
| `cli.py` | подкоманды `integrity`, `report` | не содержит бизнес-логики |

## 2. Единицы

`Parameter(name, value, units)` — неизменяемая запись. `units` обязателен, значение — из
закрытого списка (`ticks`, `min^-1`, `pct`, `rub`, `ratio`, `minutes`, `count`, `bps`).
Причина закрытого списка: свободный текст не ловит опечатку (`tick` vs `ticks`), а сравнение
ожидаемой и фактической единицы — ловит.

Тики — целые: `UnitsRegistry.as_ticks(name)` требует `units == "ticks"` **и** целого значения.
Дробные тики появляются только как промежуточный результат (`σ_τ` в тиках) и помечаются
`units="ticks"` с `flag="FRACTIONAL"`.

Реестр не разрешает дубликаты имён с разными значениями: это признак того, что два шага
объявили один параметр по-разному.

## 3. Шаг цены

Порядок: метаданные выгрузки → значение из справочника (передаёт вызывающий) → вывод по сетке
цен. Первые два источника `verified=True`; вывод — `verified=False` и `flag="UNVERIFIED"`.

Вывод по сетке: цены переводятся в целые через десятичную шкалу (`Decimal(str(price))`), затем
НОД модулей разностей соседних уникальных цен. `float` для этого не годится: `0.1` в двоичном
представлении даёт ненулевой остаток и НОД «съезжает» до 1e-9. Если уникальных цен меньше двух —
шаг не выводится (ошибка, а не догадка).

Проверка сетки (`price_on_grid`) считается в `float` с допуском на шум представления: `Decimal`
на каждом баре выгрузки (сотни тысяч строк) превращает Gate D в минуты счёта, а погрешность
деления здесь на много порядков меньше допуска. `Decimal` остаётся в выводе шага по сетке цен,
где нужна точная десятичная шкала.

## 4. Сессии и TZ

Расписание — запись в конфиге: два набора окон (будни и выходные), каждое окно — открытие и
закрытие в минутах от полуночи в TZ биржи, плюс имя TZ. `τ_session` считается в минутах до
конца **текущего** окна: `T_close − t − max(τ_liq, Δt) − buffer`; отрицательный результат
означает «вход запрещён»; вне окон — `-1`.

Наборы нужны потому, что выгрузка Collector'а содержит весь торговый день: будни почти
непрерывно 07:00–23:50 (утренняя 06:50–09:50, основная 10:00–18:40, вечерняя 19:00–23:50), а
выходные — отдельное окно 02:00–23:50. Однооконная модель отбрасывала бы две трети истории.
Границы — проектное решение (`PROJECT-DECISION:sessions`), подтверждаются шагом R0.3 сверкой с
биржевым расписанием; торговля в выходные остаётся вопросом политики этапа R1, а не R0.

DST не моделируется арифметикой: время приводится к TZ биржи через `zoneinfo`, поэтому переход
не создаёт сдвига. Для офлайн-истории это достаточно: бары уже в UTC.

## 5. Gate D

Проверки возвращают список замечаний `Finding(level, check, detail)`, где `level ∈ {critical,
warning}`. Отчёт не бросает исключение — CLI решает код возврата. Причина: на реальных данных
исследование должно продолжиться с пометками, а не падать; критичный провал — тоже исход, а не
сбой программы.

Проверки: пропуски внутри сессий (по расписанию), нулевые объёмы, дубли и монотонность `ts`,
бары вне сессий, overnight-доходности, кратность цены шагу, аномалии `|ΔP|` (порог — 20 медиан,
причина: корпоративные действия и опечатки в разы больше типичного движения), распределение
`|ΔP|` в тиках.

## 6. Дисперсии

Parkinson: `σ²_P = (ln(H/L))² / (4 ln2)`; Garman–Klass: `0.5·ln(H/L)² − (2ln2−1)·ln(C/O)²`;
Rogers–Satchell: `ln(H/C)·ln(H/O) + ln(L/C)·ln(L/O)`. Все три — в логарифмах, поэтому безразмерны.

Диагностика шума: отношение медиан range-based и close-to-close дисперсий. `> 2` — флаг
доминирования шума (bounce), `< 0.5` — флаг сглаженности.

`VR(τ) = Var(r_τ) / (τ·Var(r_1))` на десезонализованных доходностях; `σ_τ = σ_1·√(τ·VR(τ))`.
При `VR ≤ 0` (недостаточно данных или вырожденная выборка) — ошибка, а не подстановка `σ√τ`.

Десезонализация: доходность делится на медианный модуль доходности своей минуты сессии; при
меньше чем `min_observations` наблюдениях в минуте — коэффициент 1.0 и пометка `LOW_CONFIDENCE`.

## 7. Издержки

`Cost` (тики за круг) = комиссия входа + комиссия выхода + спред. Комиссия — от цены:
`rate · price / tick` тиков за сторону; спред — `spread_bps · price / 10 000 / tick` тиков.
Минимальная комиссия (если задана) применяется как `max(rate·price, min_commission)`.
Спред без измерения — `flag="UNVERIFIED"`. Стресс — отдельный вызов с множителем 1.5, а не
правка результата.

## 8. Метка и реестр

`LabelSpec(kind, horizon_bars, h_max, registered_at)` — вариант метки фиксируется до отбора;
для `fixed_horizon` `h_max = horizon_bars`, для `triple_barrier` — максимум горизонтов барьеров.

`TrialRegistry` — JSONL-файл: одна строка на опыт (`id`, `created_at`, поля политики, вариант
метки, инструменты, окно). Чтение возвращает `N_trials` для DSR. Файл не переписывается задним
числом: правка = новая строка.

## 9. CLI

`analyzer-research` с подкомандами `integrity` (Gate D по каталогу выгрузок) и `report`
(сводка артефактов: единицы, шаг цены, VR, издержки). `--out` обязателен: отчёт без места
хранения бесполезен для воспроизводимости. Код возврата: `0` — без критичных замечаний,
`1` — критичный провал Gate D, `2` — ошибка ввода.

## 10. Открытые границы

Идентификация θ, `φ*`, EV(τ) и runtime в это изменение не входят (этапы R1–R5). Пакет
проектируется так, чтобы `variance`/`costs` отдавали готовые `σ_τ` и `Cost` без переделки API.
