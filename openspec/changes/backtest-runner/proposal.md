# Proposal

## Why

Замер стратегии на реальных 1-мин свечах (8 торговых дней, `to_be.md` §3) дал однозначный
результат: система не торгует (0 сделок из 534 сигналов по SBER и 430 по SiZ6), а при обходе
фильтра экономика отрицательна — −40 % и −34 % кумулятивно при комиссии 0.04 %/сторона.
При этом судить о гипотезе по sandbox-прогонам нельзя: песочница не моделирует комиссию,
проскальзывание и очередь, а биржевые SL/TP в ней запрещены.

Штатного инструмента оценки стратегии на истории в репозитории нет: истории цен в системе
не хранится (`raw-market-data` retention 3 минуты), бэктестера и отчётности нет. Без такого
инструмента решение «вносить деньги / менять фильтр / менять стратегию» принимается вслепую.

## What Changes

- **Analyzer: пакет бэктеста** `analyzer/src/analyzer/backtest/` — пошаговый прогон исторических
  баров с переиспользованием production-расчёта (`compute_all`, `mean_reversion`): окно свечей,
  сигнал, комиссионный фильтр, риск-сайзинг, эмуляция выходов SL/TP/таймаут, агрегированный отчёт.
- **Analyzer: модель издержек по тарифу** — `investor` (0.3 %/сторона бумаги), `trader`
  (0.05 %/сторона бумаги, 0.04 % фьючерс), `premium`; признак фьючерса определяется классом
  инструмента (`SPBFUT`/`FORTS`), а не тикером. Production `CommissionFilter` не меняется.
- **Analyzer: лимит номинала позиции в модели сайзинга** — `max_position_notional_pct` от
  депозита; страхует от неисполнимых объёмов, которые даёт риск-сайзинг на малом ATR.
- **Analyzer: CLI `analyzer-backtest`** — прогон по локальной выгрузке CSV × таймфрейм × тариф,
  вывод отчёта в markdown/CSV/JSON.
- **Collector: выгрузка исторических свечей** — профиль `history-dump`: `MarketDataService.GetCandles`
  с пагинацией по лимиту запроса, запись `{ticker}_{minutes}min.csv` + sidecar `.meta.json`.
  Analyzer к T-Invest API не обращается, потому что вся сырая работа с брокерским API
  сосредоточена в Collector. В профиле не запускаются стрим, Kafka-публикация и запись
  справочника в БД; соединение с PostgreSQL не требуется.
- **Документация**: правило «сырые данные T-Invest — только через Collector» и раздел «Бэктест»
  в `README.md` и `AGENTS.md`.

## Capabilities

### New Capabilities

- `strategy-backtesting`: прогон торговой стратегии на исторических барах с моделью издержек,
  риск-сайзингом и отчётностью; контракт обмена историей между Collector и Analyzer.

### Modified Capabilities

Нет. Требования `market-data-collection` (стрим в реальном времени) не меняются: выгрузка
истории — отдельный режим Collector'а и не влияет на подписки.

## Impact

- Код: новый пакет `analyzer/src/analyzer/backtest/`, тесты `analyzer/tests/test_backtest_*.py`,
  волна 2 — `collector/.../history/` (+ профиль/CLI-режим).
- Конфигурация: `analyzer/pyproject.toml` (console script `analyzer-backtest`), `.gitignore`
  (кэш `data/history/`); новых внешних зависимостей нет.
- Данные: `data/history/*.csv` + `*.meta.json` (вне git), отчёты `reports/`.
- БД, Kafka, Flyway-миграции, `proto/` — не затрагиваются.
- Вне объёма: правка production `CommissionFilter` и `RiskManager` (Варианты 3 и 5 плана),
  эмуляция SL/TP в Trader (Вариант 2), оптимизация параметров стратегии (Вариант 4).
