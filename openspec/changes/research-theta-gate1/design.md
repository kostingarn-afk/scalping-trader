# Design — research-theta-gate1

## 1. Две оценки θ и почему одной недостаточно

**ACF-оценка (спека `buy_frame.md` §6.3).** `P* = P + η`, `Var(η) = ω²`, `σ_P² = σ²/(2θ)` →
`θ̂_obs(Δ) = θ + ln(1 + ω²/σ_P²)/Δ`; θ из интерсепта регрессии на `1/Δ`.

Реализация: лог-цена по окнам (`SessionSchedule.window_at`), пары только при точном шаге
`Δ·60 с` внутри окна, центрирование средним окна, `ρ̂(Δ) = Σxy / Σx²` по тем же парам
(знаменатель только по барам, у которых есть пара, иначе `ρ̂` механически занижается),
`θ̂ = −ln ρ̂/Δ` при `0 < ρ̂ < 1`.

**Проблема, найденная на синтетике.** Удаление среднего по окну из сильно коррелированного
ряда выбрасывает низкочастотную компоненту: на 400 независимых окнах по 400 баров при `ρ = 0.95`
получается `ρ̂(10) = 0.551` против 0.599 и `ρ̂(30) = 0.126` против 0.215. Смещение растёт с Δ,
поэтому чистый случайный проход даёт `θ̂ = 0.0095` (± 0.0022 по сессиям) — **Gate 1 по CI
проходил бы ряд без возврата**. Bootstrap это не ловит: он меряет разброс между сессиями,
а не смещение метода.

**Дисперсионная оценка (добавлена).** Для OU `Var(x_{t+Δ} − x_t) = (σ²/θ)(1 − e^{−θΔ}) + 2ω²`.
Приращения инвариантны уровню окна, поэтому среднее удалять не нужно. Оценка — профильный МНК:
модель линейна по `A = σ²/θ` и `2ω²`, поэтому при фиксированной θ коэффициенты находятся
обычным МНК, и остаётся одномерный поиск по θ (сетка по лог-θ 240 точек + уточнение 60 точек).

`curve_fit` отвергнут: с нижней границей `θ ≥ 1e-6` он возвращал на случайном блуждании
`θ = 0.038` с `2ω² → 0`, то есть ложную возвратность из-за разброса масштабов
(`A ~ 1e-4`, `2ω² ~ 1e-6`).

**Ограничение метода, объявленное явно.** На случайном блуждании `v(Δ) ∝ Δ`: профиль МНК
вырожден (идентифицируется только произведение `A·θ`), и минимум лежит на нижней границе
сетки. Это значит «возврат не идентифицируется», а не «θ = 1e-5», поэтому оценка получает
`identified = False`, а Gate 1 отклоняет инструмент. Граница установлена на
`VARIANCE_THETA_FLOOR = 1e-5` и вынесена в константу, чтобы её нельзя было подменить молча.

## 2. Нулевая полоса вместо «CI не содержит нуля»

Вердикт строится сравнением с распределением **той же процедуры на случайном блуждании**
с теми же длинами окон (`NullBand`). Полоса — 2.5–97.5 перцентили; гейт смотрит на верхнюю
границу. Пустой набор реплик даёт `None` для соответствующей границы, а не `(0, 0)`: «полосы
нет» обязано быть отличимо от «полоса нулевая», иначе критерий проходит без проверки.

Почему это корректно: обе оценки масштабно-инвариантны (`ρ` и `v(Δ)/v(1)` не зависят от
волатильности), поэтому полоса зависит только от геометрии окон и сетки Δ. Симуляция ведётся
в единицах шага, без цен. Полоса кэшируется по `(длины окон, Δ, reps, seed)`.

Стоимость: 100 реплик на инструмент; прогон 20 инструментов — 71 с (окно 8 недель, ~40 окон).

## 3. Fallback: плато signature plot

Если CI наклона содержит 0 и хвост `θ̂(Δ)` устойчив (разброс ≤ 20 % на Δ ≥ 10), θ берётся как
медиана хвоста, метод `PLATEAU`. Причина: при отсутствии шумовой поправки интерсепт регрессии
численно нестабилен. CI в этом случае — перцентили бутстреп-значений плато, а не интерсепта,
и сравнение с полосой идёт по границе `acf_plateau`.

Выбор оценки вынесен в чистую функцию `_select_estimate`: иначе на реальных данных (наклон
значим) ветка остаётся непокрытой тестами.

## 4. Gate 1

Проходит, если одновременно:

1. нижняя граница CI оценки > 0;
2. отношение верхней и нижней границ CI `t_{1/2}` ≤ 2 (ровно 2 — проходит);
3. `θ` ACF выше верхней границы полосы для своего метода;
4. дисперсионная θ выше своей полосы и `identified = True`.

Диагностические флаги (не блокируют): `estimators` при расхождении ACF/дисперсионная вне
`[0.67; 1.5]`, `variance_margin` при запасе над полосой меньше 1.25×, `horizon` в CLI при
`t½ > τ_cap`, `SUGGEST_ESCALATION` при `θ_used ≤ 0.02`.

Почему расхождение не блокирует: ACF смещена вверх (удаление среднего), дисперсионная вниз
(слабый шумовой член) — на данных отношение достигает 2.9. Порог на разницу двух смещённых
оценок был бы взят «на глаз»; блокирует только статистическая ось.

Вердикт по инструменту; прогон останавливается, если Gate 1 провален на всех.

## 5. OU-параметры

- `θ_used` — дисперсионная оценка, если идентифицирована, иначе ACF.
- `σ` — из дисперсионной модели: `σ² = A·θ`, то есть диффузия без микроструктурного шума.
  `sigma_naive` (СКО десезонных доходностей) публикуется рядом как диагностика: она включает шум
  и проходы через пропуски и на данных отличается в 0.60–0.67× (то есть завышена).
- `σ_P = σ/√(2θ_used)`.
- `μ` — среднее лог-цены внутри окон (якорь `A_t`), единица `log_price`.
- attenuation `1/(1 + κ)`, κ — шумовое отношение из ACF-регрессии; при CI наклона, содержащем 0,
  ставится флаг `CONSERVATIVE`.
- `ρ_model(τ) = −√((1 − e^{−θτ})/2)` — диагностика для Gate 0b, в Gate 0 не подставляется.
- `fit_ou` отказывает, если Gate 1 не пройден, и принимает `registry_id` записи опыта.

## 6. Артефакты, окно оценки и CLI

Окно оценки — `--weeks` (по умолчанию 8, допустимо 4–8 по §6.3); `0` — вся история
в диагностическом режиме. Для каждого инструмента окно фиксируется в артефакте
(`estimation_window`: `weeks`, `from`, `to`, `mode`), поэтому длинная история не может быть
принята за отчётную.

Четыре артефакта, каждый в конверте `build_artifact` (единицы, `n`, метод, флаги):

| Файл | `name` | Содержание |
|---|---|---|
| `theta-invariance.json` | `theta_invariance_regression` | точки `Δ, ρ̂, θ̂`, интерсепт, наклон, CI, метод, вердикт, окно |
| `signature-plot.json` | `signature_plot` | `θ̂(Δ)`, `ρ̂(Δ)` и число пар по инструментам |
| `null-band.json` | `null_band` | границы полосы на инструмент, число реплик и окон |
| `ou-fit.json` | `ou_fit` | θ (обе оценки и использованная), σ, `sigma_naive`, σ_P, μ, attenuation, ρ_model, `registry_id` |

`theta.md` — человекочитаемая сводка (вердикты, причины провала, signature plot, OU-параметры).

CLI: `analyzer-research theta --data-dir … --out … [--weeks 8] [--deltas … | --escalate]
[--bootstrap 200] [--null-reps 100] [--registry …]`. Код возврата: 0 — Gate 1 пройден хотя бы
одним инструментом, 1 — провал на всех, 2 — ошибка ввода. `--deltas` и `--escalate`
взаимоисключающие; дубли Δ схлопываются, порядок нормализуется.

`ThetaError` на отдельном инструменте (нет баров в окнах) не прерывает прогон: инструмент
получает `THETA_UNDEFINED` с причиной.

## 7. Границы

EV(τ), τ*, правило удержания (R3) и Gate 0b (R4) не входят. `OuFit` отдаёт R3 θ, σ_P, CI и якорь
`μ`. Вопрос «пригоден ли горизонт при `t½ > τ_cap`» решается в R3 (`PROJECT-DECISION:r3-slow-reversion`
в `to_do.md` §4–§5), а не правкой гейта.
