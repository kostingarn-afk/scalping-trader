# Proposal

## Why

Gate 0a пройден (19 из 20), но он отвечает только на вопрос «хватает ли движения». Следующий шаг
по §16 `buy_frame.md` — идентификация параметров OU: `θ` (скорость возврата), `σ`, `σ_P`,
`ρ_model`, и **Gate 1**: можно ли вообще измерять θ на этих данных.

Проверка метода на синтетике показала, что одна оценка из спеки (§6.3, ACF лог-цены с
удалением среднего окна) недостаточна: на чистом случайном блуждании она даёт
`θ̂ = 0.0095` с узким CI и **проходит Gate 1**. Поэтому к ней добавляется независимая
дисперсионная оценка и нулевая полоса — распределение той же процедуры на случайном блуждании
с той же геометрией окон. Спека не отменяется: ACF-оценка остаётся обязательным артефактом,
меняется только основание вердикта.

## What Changes

- **θ̂(Δ)** — ACF лог-цены на Δ ∈ {1, 2, 3, 5, 10, 15, 30} мин внутри торговых окон;
  пары только при точном шаге времени и внутри одного окна.
- **Инвариантность** — регрессия `θ̂_obs(Δ)` на `1/Δ`: интерсепт = шум-скорректированная θ,
  slope = логарифм шумового отношения; CI — блочный bootstrap по сессиям.
- **Дисперсионная оценка** — `Var(x_{t+Δ} − x_t) = (σ²/θ)(1 − e^{−θΔ}) + 2ω²`, профильный МНК,
  признак неидентифицируемости при минимуме на границе сетки.
- **Нулевая полоса** — та же процедура на случайном блуждании с теми же длинами окон;
  зависит только от геометрии, кэшируется.
- **Gate 1** — CI оценки не содержит 0, CI `t_{1/2}` не шире двукратного, обе оценки выше своих
  полос, дисперсионная оценка идентифицирована.
- **OU-параметры** — `σ` из дисперсионной модели, `σ_P`, `μ`, attenuation, `ρ_model` как
  диагностика; `θ_used` — дисперсионная оценка; наивная σ рядом как диагностика.
- **Окно оценки** — последние 4–8 недель (`--weeks`, по умолчанию 8), фиксируется в registry
  и артефакте; вся история — только явный диагностический режим.
- **CLI** — подкоманда `theta`, режим `--escalate` (сетка Δ до 60 при θ ≤ 0.02), четыре
  артефакта: `theta_invariance_regression`, `signature_plot`, `null_band`, `ou_fit`.

Не входит: EV(τ), τ*, правило удержания (R3), Gate 0b (R4), runtime (R5).

## Результат прогона (для сведения)

Окно оценки 8 недель (`bda1fd928038`): Gate 1 пройден 4 из 20; `θ` 0.0053–0.0111 мин⁻¹,
`t_{1/2}` 62.6–131.8 мин при `τ_cap = 60` у всех 20 инструментов. Эскалация до Δ = 60
(`2c4d9ebdd424`) даёт 5 из 20 (добавляется SBER) — порядок θ и вывод не меняются. На всей
истории (10 месяцев, диагностический режим) проходили 14 из 20: короткое окно расширяет нулевую
полосу, потому что независимых окон меньше. Это ставит вопрос о пригодности OU-модели на
горизонте скальпинга — решение по нему (`PROJECT-DECISION:r3-slow-reversion`) записано в
`to_do.md` §4–§5 и относится к R3.
