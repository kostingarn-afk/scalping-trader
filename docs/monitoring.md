## 1. Иерархия триггеров переобучения

Триггеры разделены на 4 уровня строгости. Срабатывание любого триггера уровня 1-2 требует немедленного вмешательства. Уровни 3-4 требуют анализа и подтверждения.

### Уровень 1: Статистические тесты структурных сдвигов (строгие)

**CUSUM-of-Squares Test (Brown-Durbin-Evans)** — основной тест для скальпинга, чувствителен к сдвигам волатильности (гетероскедастичность):
$$S_t^{(2)} = \sum_{i=1}^{t} \left(\frac{\hat{\epsilon}_i^2}{\hat{\sigma}^2} - 1\right), \quad \text{сигнал при } |S_t^{(2)}| > c_{\alpha}\sqrt{t}$$
где $\hat{\epsilon}_i$ — остатки модели, $\hat{\sigma}^2$ — оценка дисперсии на train-выборке, $c_{\alpha}$ — критическое значение (табличное или через bootstrap).

*Почему не стандартный CUSUM:* финансовые ряды имеют гетероскедастичность (кластеризация волатильности), стандартный CUSUM теряет мощность.

**Bai-Perron Test** для обнаружения множественных структурных сдвигов. Минимизирует сумму квадратов остатков при $m$ сдвигах:
$$\min_{\tau_1, \ldots, \tau_m} \sum_{j=0}^{m} \sum_{t=\tau_j+1}^{\tau_{j+1}} (y_t - \mu_j)^2$$
*Практическая реализация:* использовать динамическое программирование (сложность $O(N^2 m)$), не полный перебор.

**Chow Test** для проверки гипотезы о смене режима в известную дату $T_b$ (например, после изменения регламента биржи):
$$F = \frac{(RSS_p - RSS_{ur}) / k}{RSS_{ur} / (n_1 + n_2 - 2k)}$$
где $RSS_p$ — остаточная сумма квадратов для pooled выборки, $RSS_{ur}$ — для раздельных выборок до и после $T_b$, $k$ — число параметров.

**Wasserstein Distance** для сравнения распределений (замена KL Divergence):
$$W_2^2(P_{train}, P_{live}) = \int_0^1 \left(F_{train}^{-1}(u) - F_{live}^{-1}(u)\right)^2 du$$
*Практическая реализация:* для ускорения использовать analytical approximation через moments:
$$W_2^2 \approx (\mu_{train} - \mu_{live})^2 + (\sigma_{train} - \sigma_{live})^2$$
Порог срабатывания: 95-й перцентиль исторических значений $W_2$, оценённый через bootstrap (100 итераций для daily, 1000 для weekly).

---

### Уровень 2: Дрейф параметров (с учётом uncertainty)

**Сравнение через доверительные интервалы** (не через фиксированный процент):
$$\text{Триггер если: } \hat{\theta}_{train} \pm t_{\alpha/2, n-1} \cdot \text{SE}(\hat{\theta}_{train}) \quad \text{не пересекается с} \quad \hat{\theta}_{live} \pm t_{\alpha/2, m-1} \cdot \text{SE}(\hat{\theta}_{live})$$

**Для модели Орнштейна-Уленбека:** Если half-life $t_{1/2}^{live} = \ln 2 / \hat{\theta}_{live}$ выходит за 95% CI от $t_{1/2}^{train}$ — триггер переобучения.

**Для GARCH:** Если долгосрочная дисперсия $\omega$ структурно сдвинулась (проверка через CUSUM-of-squares на параметре $\omega$) — триггер.

**Для процессов Хоукса:** Если branching ratio $n = \alpha/\beta$ структурно сдвинулся выше 0.8 (проверка через bootstrap CI) — триггер смены режима с mean reversion на momentum.

---

### Уровень 3: Деградация предсказательной силы

**Deflated Sharpe Ratio (DSR)** Lopez de Prado (строгая формула):
$$\widehat{SE}(SR) = \sqrt{\frac{1 + \frac{1}{2}\gamma_2 \cdot SR^2 + \frac{\gamma_3 - 3}{4}SR^4}{T - 1}}$$
$$DSR = \Phi\left(\frac{SR - \hat{SR}^*}{\widehat{SE}(SR)}\right)$$
где:
- $\gamma_2, \gamma_3$ — skewness и kurtosis returns,
- $\hat{SR}^*$ — бенчмарк (медианный Sharpe случайных стратегий или целевой минимум),
- $\Phi$ — функция стандартного нормального распределения.

**Триггер:** $DSR < 0.5$ (или другой порог, обоснованный исторически).

**Alpha Decay Curve** — две параметризации (выбор через AIC/BIC):

*Экспоненциальная (для momentum):*
$$\alpha(\tau) = \alpha_0 \cdot e^{-\lambda \tau}$$

*Степенная (для mean reversion, учитывает long memory):*
$$\alpha(\tau) = \alpha_0 \cdot (1 + \tau/\tau_0)^{-\beta}$$

**Оценка параметров:** Non-linear regression на исторических циклах переобучения.

**Half-life alpha:**
- Экспоненциальная: $t_{1/2}^{alpha} = \ln 2 / \lambda$
- Степенная: $t_{1/2}^{alpha} = \tau_0 \cdot (2^{1/\beta} - 1)$

**Триггер:** $\alpha(\tau) < \alpha_{min}$, где $\alpha_{min}$ — минимальная альфа, покрывающая издержки $(C + S)$.

**Brier Score** для вероятностных моделей:
$$BS = \frac{1}{N}\sum_{i=1}^{N}(\hat{p}_i - o_i)^2$$
где $\hat{p}_i$ — предсказанная вероятность, $o_i \in \{0, 1\}$ — фактический исход.

**Триггер:** $BS > BS_{threshold}$, где $BS_{threshold}$ — 95-й перцентиль исторических значений (bootstrap, 100 итераций).

---

### Уровень 4: Мета-мониторинг модели

**Prediction Confidence Distribution:** Если модель "уверена" на 90% в 50% случаев (или наоборот), это признак переобучения или недообучения.

**Калибровка:** Построить reliability diagram — график предсказанных vs фактических вероятностей по бинам. Если отклонение от диагонали > 10% — триггер.

**Autocorrelation остатков модели:** Если появилась значимая автокорреляция (тест Ljung-Box, $p < 0.05$), модель не добирает сигнал — триггер re-specification.

## 2. Поправка на множественное тестирование

При одновременном мониторинге $m$ метрик **с p-значениями** (CUSUM, Chow, Ljung-Box) вероятность хотя бы одного ложного срабатывания:
$$P(\text{хотя бы 1 FP}) = 1 - (1 - \alpha)^m$$

**Поправка Бонферрони (консервативная):**
$$\alpha_{adjusted} = \frac{\alpha}{m}$$

**False Discovery Rate (FDR) Бенджамини-Хохберга (более мощная):**
Упорядочить $p$-значения: $p_{(1)} \leq p_{(2)} \leq \ldots \leq p_{(m)}$.
Найти максимальное $k$ такое, что:
$$p_{(k)} \leq \frac{k}{m} \cdot \alpha$$
Отвергнуть гипотезы $H_{(1)}, \ldots, H_{(k)}$.

**Важно:** FDR применим только к метрикам с p-значениями. Для метрик без p-value (Wasserstein, Brier Score) использовать bootstrap-пороги, не FDR.

**Рекомендация:** Использовать FDR для триггеров уровней 3-4, Бонферрони для уровня 1 (критические структурные сдвиги).

## 3. Протокол безопасного переобучения (CPCV)

Классический walk-forward не учитывает serial correlation и lookahead bias. Использовать **Combinatorial Purged Cross-Validation (CPCV)**:

### Шаг 1: Определение максимального горизонта
Для всех моделей определить горизонты прогноза $h_1, h_2, \ldots, h_K$. Взять максимум:
$$h_{max} = \max_k h_k$$

### Шаг 2: Purging (устранение lookahead через label information)
Из train-выборки удаляются все примеры, чьи окна $[i, i+h_{max}]$ пересекаются с test-выборкой:
$$\text{Train} = \{i : [i, i+h_{max}] \cap \text{Test} = \emptyset\}$$

### Шаг 3: Embargo (устранение autocorrelation leakage)
Добавить буфер $\delta$ между train и test:
$$\text{Train} = \{i : i < \min(\text{Test}) - \delta\}$$
где $\delta \approx 3 \times$ autocorrelation horizon (оценивается через ACF).

### Шаг 4: Block-based Combinatorial splitting
Вместо полного $\binom{N}{k}$ (астрономическое число), использовать block-based CPCV:
- Разбить данные на $\phi = 3$ группы (например, по 83000 баров для годовых данных).
- Сформировать $\binom{\phi}{k}$ комбинаций (при $\phi=3, k=2$: 3 комбинации).
- Для каждой комбинации: одна группа — test, остальные — train (с purging и embargo).

### Шаг 5: Deflated метрики
Для каждой комбинации вычислить DSR, а не обычный Sharpe.

### Шаг 6: Агрегация
Итоговая оценка: медиана DSR по всем комбинациям + 95% CI через bootstrap (100 итераций).

## 4. Разделение Re-estimation и Re-specification

| Аспект | Re-estimation | Re-specification |
|--------|---------------|------------------|
| **Что меняется** | Параметры $\theta$ (например, $\theta, \mu$ в OU) | Структура модели (например, переход от OU к Hawkes) |
| **Частота** | Еженедельно / по триггеру уровней 2-3 | Ежеквартально / по событию (триггер уровня 1) |
| **Протокол валидации** | Purged walk-forward (упрощённый CPCV) | Полный CPCV + shadow trading |
| **Риск** | Переобучение на шум (низкий) | Потеря alpha (высокий) |
| **Метрика успеха** | Стабильность DSR, узость CI параметров | Рост out-of-sample RAE, статистическая эквивалентность |
| **Пример** | Пересчёт $\hat{\theta}$ на последних 4 неделях | Замена OU-модели на HMM с 3 режимами |
| **Cooldown period** | $t_{cooldown} = 2 \cdot t_{1/2}^{alpha}$ | $t_{cooldown} = 2 \cdot t_{1/2}^{alpha}$ |

## 5. Математически обоснованная частота переобучения

Вместо календарного правила — **half-life alpha**:
$$T_{retrain} \approx t_{1/2}^{alpha}$$

**Протокол оценки $t_{1/2}^{alpha}$:**
1. Зафиксировать исторические циклы переобучения (по датам) за последние 6-12 месяцев.
2. Для каждого цикла измерить $\alpha(\tau)$ на out-of-sample (через $\tau$ дней после переобучения).
3. Построить кривую decay, оценить параметры ($\lambda$ или $\beta, \tau_0$) через non-linear regression.
4. Выбрать параметризацию (экспоненциальная vs степенная) через AIC/BIC.
5. Bootstrap CI для $t_{1/2}^{alpha}$ (1000 итераций).

**Типичные значения для скальпинга (оценены эмпирически):**

| Тип модели | $t_{1/2}^{alpha}$ | Обоснование |
|------------|-------------------|-------------|
| Микроструктура (OBI, VPIN, $\kappa$) | 1-3 дня | Стакан и поток ордеров меняются мгновенно |
| Mean Reversion (OU: $\theta, \mu$) | 2-4 недели | Требуется достаточно данных для оценки скорости возврата |
| Волатильность (GARCH: $\sigma_t$) | Рекурсивно (каждый бар) | Не переобучение, а обновление через рекурсивную формулу |
| HMM-режимы (матрица переходов) | 2-3 месяца | Макрорежимы меняются медленно |
| ML-модели (LightGBM/XGBoost) | 1-2 месяца | Полное переобучение на скользящем окне |

## 6. Протокол Shadow Trading и Statistical Equivalence

Перед полным переходом на новую модель:

### Shadow Trading (ускоренный для скальпинга)
Новая модель работает параллельно **2-3 дня** (не 1-2 недели, из-за быстрого decay alpha) **без реальных ордеров**. Используется sequential testing (Wald's SPRT) для ранней остановки:
$$\text{Stop if: } \sum_{i=1}^{n} \ln \frac{f_{new}(R_i)}{f_{old}(R_i)} > \ln \frac{1-\beta}{\alpha} \quad \text{(принять новую)}$$
$$\text{Stop if: } \sum_{i=1}^{n} \ln \frac{f_{new}(R_i)}{f_{old}(R_i)} < \ln \frac{\beta}{1-\alpha} \quad \text{(отклонить)}$$
где $\alpha = 0.05, \beta = 0.20$.

### Statistical Equivalence Test
Проверка гипотезы:
$$H_0: \mu_{new} - \mu_{old} \leq -\Delta$$
$$H_1: \mu_{new} - \mu_{old} > -\Delta$$
где $\Delta$ — минимальный практически значимый эффект (MDES), например, $\Delta = 0.5 \cdot (C + S)$.

**Тест (Two One-Sided Tests, TOST):**
$$t = \frac{(\bar{R}_{new} - \bar{R}_{old}) - (-\Delta)}{\sqrt{\frac{s_{new}^2}{N_{new}} + \frac{s_{old}^2}{N_{old}}}}$$
Если $t > t_{\alpha, df}$ и $p < 0.05$ — новая модель статистически эквивалентна или лучше старой.

**Переход:** Только если equivalence test пройден **и** DSR новой модели > DSR старой.

## 7. Обработка каскадных срабатываний и edge cases

### Матрица приоритетов при множественных срабатываниях

| Сработавшие триггеры | Действие | Обоснование |
|----------------------|----------|-------------|
| Chow test на дату события | Только re-specification | Структурное изменение требует смены модели |
| CUSUM + дрейф параметров | Re-estimation | Локальный сдвиг, структура сохраняется |
| Все триггеры уровня 1 | Re-specification + полная валидация | Системный шок, требуется пересмотр стратегии |
| Только уровень 3-4 | Наблюдение, без вмешательства | Возможно, временная деградация |

### Cooldown period после переобучения
После любого re-estimation или re-specification модель работает **минимум** $t_{cooldown} = 2 \cdot t_{1/2}^{alpha}$ без вмешательства. Это предотвращает бесконечный цикл переобучений на шум.

### Rollback mechanism
Если после re-estimation $DSR_{new} < DSR_{old} - \Delta_{rollback}$ (где $\Delta_{rollback} = 0.1$), откатить к старой версии модели. Это защищает от overfitting на локальный режим.

### Фильтр внутридневных паттернов
Триггеры применяются только к "нормальным" часам торговли (например, 10:00-17:00). Данные открытия/закрытия сессии, обеденного провала исключаются из расчёта триггеров, чтобы избежать ложных срабатываний на структурных паттернах.

## 8. Финальный чек-лист мониторинга

### Ежедневно (после закрытия сессии, только "нормальные" часы):
- [ ] Пересчёт GARCH-волатильности (рекурсивно, не переобучение).
- [ ] Мониторинг Brier Score и confidence calibration.
- [ ] CUSUM-of-squares тест на структурный сдвиг (с поправкой Бонферрони, если мониторится несколько метрик).
- [ ] Проверка autocorrelation остатков модели (Ljung-Box).
- [ ] *Исключить:* данные открытия/закрытия сессии из расчёта триггеров.

### Еженедельно (например, в выходные):
- [ ] Re-estimation параметров OU / Hawkes на purged rolling window (последние 4-8 недель).
- [ ] Проверка $W_2(P_{train}, P_{live})$ с analytical approximation или bootstrap (100 итераций).
- [ ] Обновление alpha decay curve (выбор параметризации через AIC/BIC).
- [ ] Расчёт Deflated Sharpe Ratio за последнюю неделю (строгая формула с $\widehat{SE}(SR)$).
- [ ] Применение FDR-поправки к p-значениям тестовых метрик (CUSUM, Chow, Ljung-Box).
- [ ] Проверка cooldown period: если прошло < $2 \cdot t_{1/2}^{alpha}$ с последнего переобучения, пропустить re-estimation.

### Ежемесячно:
- [ ] Полный block-based CPCV-валидация всех моделей ($\phi = 3$ группы, purging с $h_{max}$, embargo).
- [ ] Пересчёт Deflated Sharpe Ratio на out-of-sample.
- [ ] Решение о re-specification на основе FDR-скорректированных триггеров уровня 1 (матрица приоритетов).
- [ ] Анализ half-life alpha: если $t_{1/2}^{alpha}$ сократился — увеличить частоту re-estimation.
- [ ] Оценка $t_{1/2}^{alpha}$ по протоколу (non-linear regression + bootstrap CI).

### По событию (регламент биржи, смена ликвидности, структурный шок):
- [ ] Полный Chow test на дату события.
- [ ] Перекалибровка модели исполнения (Almgren-Chriss: $\eta, \lambda_{risk}$).
- [ ] Если сработал Chow test → re-specification (не re-estimation).
- [ ] Shadow trading (2-3 дня) с sequential testing (Wald's SPRT).
- [ ] Statistical equivalence test перед полным переходом.

## 9. Критические предупреждения

⚠️ **Если вы вынуждены переобучать модель чаще, чем раз в неделю, чтобы она просто "не сливала"**, это признак того, что вы моделируете шум, а не математическое ожидание. Истинная альфа в скальпинге деградирует неделями или месяцами, а не днями (если только не произошло структурного шока).

⚠️ **Никогда не переобучайте на test-выборке.** Если после переобучения вы тестируете на тех же данных — это data leakage. Используйте строгий CPCV с purging ($h_{max}$) и embargo.

⚠️ **Поправка на множественное тестирование обязательна.** Если вы мониторите 10+ метрик с p-значениями без FDR, 40% "срабатываний" будут ложными. Для метрик без p-value использовать bootstrap-пороги.

⚠️ **Re-estimation ≠ Re-specification.** Не меняйте структуру модели только потому, что параметры "немного сдвинулись". Сначала проверьте, выходит ли сдвиг за доверительный интервал.

⚠️ **Shadow training обязателен для re-specification.** Никогда не переходите на новую структуру модели без 2-3 дней параллельной работы с sequential testing и statistical equivalence test.

⚠️ **Cooldown period обязателен.** После переобучения дайте модели минимум $2 \cdot t_{1/2}^{alpha}$ без вмешательства, иначе возникнет бесконечный цикл переобучений.

⚠️ **Rollback при ухудшении.** Если re-estimation ухудшил DSR, откатите к старой версии. Overfitting на недавние данные — частая ошибка.

⚠️ **Фильтр внутридневных паттернов.** Не применяйте триггеры к данным открытия/закрытия сессии — это структурные паттерны, не сдвиги.
