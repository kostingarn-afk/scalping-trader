# 📊 T-Invest API: Полный обзор для системы скальпинга

## 1. 🔗 Протокол и подключение

### **Основной протокол: gRPC**
- **Bidirectional streaming** — двунаправленный стриминг для real-time данных [[1]]
- Поддержка HTTP/2 для низкой задержки
- Protocol Buffers для сериализации

### **Адреса серверов:**
| Окружение | Адрес |
|-----------|-------|
| **Production** | `invest-public-api.tinkoff.ru:443` [[2]] |
| **Sandbox** | `sandbox-invest-public-api.tinkoff.ru:443` [[2]] |
| **WebSocket proxy** | `wss://invest-public-api.tinkoff.ru/ws/` [[3]] |

### **Аутентификация:**
```
Authorization: Bearer <your_token>
```
Передается в metadata каждого gRPC-запроса [[2]]

## 2. 🔑 Токены доступа

### **Типы токенов:**

| Тип | Назначение | Права |
|-----|-----------|-------|
| **Readonly** | Только чтение данных | Портфель, котировки, история |
| **Full-access** | Полные права | Все операции включая торговлю [[4]] |
| **Account-specific** | Доступ к одному счету | Readonly или Full-access [[4]] |
| **Sandbox** | Тестирование в песочнице | Эмуляция торговли без реальных денег [[4]] |

### **Срок жизни токена:**
- **3 месяца** с даты последнего использования [[4]]
- При ошибке `40003` токен нужно перевыпустить

### **Важно для скальпинга:**
⚠️ Сделки **свыше 6 млн рублей / $100,000 / €100,000** требуют подтверждения кодом и **недоступны через API** [[4]]

## 3. 📈 Сервисы API

### **3.1. InstrumentsService** — Информация об инструментах

**Назначение:** Получение списка и метаданных торговых инструментов

**Ключевые методы:**
- `Shares` — список акций
- `Bonds` — список облигаций
- `Futures` — список фьючерсов
- `Currencies` — список валют
- `Etfs` — список ETF
- `Options` — список опционов
- `GetInstrumentBy` — получить инструмент по ID (FIGI/Ticker/UID)
- `FindInstrument` — поиск по названию
- `TradingSchedules` — расписание торгов
- `GetDividends` — дивиденды
- `GetBondCoupons` — купоны облигаций

**Идентификаторы инструментов:**
| Тип | Описание | Пример |
|-----|----------|--------|
| **UID** | Уникальный идентификатор (основной) | `83dbb109-60dc-4f30-8b77-1234567890ab` |
| **FIGI** | Financial Instrument Global Identifier | `BBG004730N88` |
| **Ticker + ClassCode** | Тикер + класс-код секции | `SBER` + `TQBR` |
| **ISIN** | International Securities ID | `RU000A1025M3` |
| **PositionUID** | ID позиции инструмента | Для фьючерсов/опционов |

**Метаданные инструмента включают:**
- `lot` — лотность
- `min_price_increment` — минимальный шаг цены
- `trading_status` — торговый статус
- `currency` — валюта расчетов
- `api_trade_available_flag` — доступность для API-торговли
- `klong/kshort`, `dlong/dshort` — маржинальные коэффициенты

---

### **3.2. MarketDataService** — Исторические котировки

**Назначение:** Получение исторических данных

**Ключевые методы:**
- `GetCandles` — исторические свечи (OHLCV)
- `GetLastPrices` — последние цены
- `GetLastTrades` — последние обезличенные сделки
- `GetOrderBook` — стакан по инструменту
- `GetTradingStatus` — торговый статус
- `GetClosePrices` — цены закрытия сессии

**Параметры свечей:**
- Интервалы: 1 мин, 5 мин, 15 мин, 1 час, 1 день
- Максимум свечей за запрос: зависит от интервала
- Данные доступны за последние несколько лет

---

### **3.3. MarketDataStreamService** — ⚡ Real-time стримы (КРИТИЧНО для скальпинга!)

**Назначение:** Получение биржевых данных в реальном времени через стримы

**Типы стримов:**

#### **Bi-directional Stream (`MarketDataStream`)**
- Клиент отправляет подписки
- Сервер отправляет данные
- Одно соединение — много подписок

#### **Server-side Stream (`MarketDataServerSideStream`)**
- Сервер управляет стримом
- Клиент только подписывается

**Типы подписок:**

| Тип данных | Описание | Частота обновлений |
|------------|----------|-------------------|
| **Candles** | Свечи (OHLCV) | По закрытию или каждую секунду |
| **OrderBook** | Стакан заявок | При каждом изменении (10 уровней) |
| **Trades** | Лента обезличенных сделок | Каждая сделка |
| **LastPrice** | Последние цены | При каждом изменении |
| **Info** | Торговые статусы инструментов | При изменении статуса |

**Лимиты в одном стрим-соединении:**
- **300 подписок** суммарно на свечи, стаканы и сделки [[5]]
- **Без ограничений** на подписки Info (статусы) [[5]]

**Пример подписки на стакан:**
```protobuf
SubscribeOrderBookRequest {
    subscription_action: SUBSCRIPTION_ACTION_SUBSCRIBE,
    instrument_id: "BBG004730N88",  // FIGI or UID
    depth: 10  // глубина стакана
}
```

**Пример подписки на свечи:**
```protobuf
SubscribeCandlesRequest {
    subscription_action: SUBSCRIPTION_ACTION_SUBSCRIBE,
    instrument_id: "BBG004730N88",
    interval: SUBSCRIPTION_INTERVAL_ONE_MINUTE,
    waiting_close: false  // true = ждать закрытия свечи
}
```

### **3.4. OrdersService** — Управление ордерами

**Назначение:** Выставление, отмена и мониторинг торговых заявок

#### **Метод `PostOrder` — Выставление заявки**

**Запрос (`PostOrderRequest`):**
```protobuf
{
    instrument_id: "BBG004730N88",  // FIGI или UID
    quantity: 10,                    // количество ЛОТОВ (не штук!)
    price: {                         // цена за 1 инструмент
        units: 150,
        nano: 500000000             // 150.50
    },
    direction: ORDER_DIRECTION_BUY,
    account_id: "your_account_id",
    order_type: ORDER_TYPE_LIMIT,   // тип ордера
    order_id: "unique_idempotency_key"  // для идемпотентности (max 36 символов)
}
```

**Типы ордеров (`OrderType`):**
| Тип | Значение | Описание |
|-----|----------|----------|
| `ORDER_TYPE_LIMIT` | 1 | Лимитная заявка |
| `ORDER_TYPE_MARKET` | 2 | Рыночная заявка |
| `ORDER_TYPE_BESTPRICE` | 3 | Лучшая цена (исполнение по лучшей цене стакана) |

**Направление (`OrderDirection`):**
- `ORDER_DIRECTION_BUY` (1) — покупка
- `ORDER_DIRECTION_SELL` (2) — продажа

**Ответ (`PostOrderResponse`):**
```protobuf
{
    order_id: "exchange_order_id",
    execution_report_status: EXECUTION_REPORT_STATUS_NEW,
    lots_requested: 10,
    lots_executed: 0,
    initial_order_price: {currency: "rub", units: 1505, nano: 0},
    initial_commission: {currency: "rub", units: 0, nano: 450000000},
    initial_security_price: {units: 150, nano: 500000000},
    message: ""
}
```

#### **Другие методы:**
- `CancelOrder` — отмена заявки
- `GetOrderState` — статус конкретной заявки
- `GetOrders` — список всех активных заявок
- `ReplaceOrder` — изменение существующей заявки (цена/количество)

#### **Статусы заявок (`OrderExecutionReportStatus`):**
| Статус | Описание |
|--------|----------|
| `EXECUTION_REPORT_STATUS_NEW` | Новая, принята биржей |
| `EXECUTION_REPORT_STATUS_PARTIALLYFILL` | Частично исполнена |
| `EXECUTION_REPORT_STATUS_FILL` | Полностью исполнена |
| `EXECUTION_REPORT_STATUS_CANCELLED` | Отменена пользователем |
| `EXECUTION_REPORT_STATUS_REJECTED` | Отклонена биржей |

### **3.6. StopOrdersService** — Стоп-ордера (ВАЖНО для скальпинга!)

**Назначение:** Автоматическая защита позиций

**Метод `PostStopOrder`** — выставление стоп-заявки

**Типы стоп-ордеров:**
- **Stop-Loss** — закрытие при достижении цены убытка
- **Take-Profit** — фиксация прибыли при целевой цене
- **Stop-Limit** — лимитная заявка, активируемая по стоп-цене

**Преимущество для скальпинга:**
- Стоп-ордера исполняются **на стороне брокера**
- Работают даже если ваш Java-модуль упал
- Минимальная задержка исполнения

## 4. 🚦 Лимиты API (КРИТИЧНО для скальпинга!)

### **4.1. Unary-методы (обычные запросы)**

| Сервис | gRPC (запросов/мин) | REST (запросов/мин) |
|--------|---------------------|---------------------|
| **Инструменты** | 200 | 100 |
| **Счета** | 100 | 50 |
| **Операции** | 200 | 100 |
| **Котировки** | 300 | 150 |
| **Ордера (общий)** | 100 | 50 |
| **└─ `getOrders`** | 200 | 100 |
| **└─ `postOrder`** | **300** | 150 |
| **└─ `cancelOrder`** | 100 | 50 |
| **Стоп-ордера** | 50 | 25 |
| **Песочница** | 200 | 100 |

### **4.2. Stream-соединения (грейды)**

Лимиты зависят от **количества исполненных заявок** за последние 30 дней:

| Грейд | Условия исполнения | Stream котировок | Stream ордеров | Stream операций |
|-------|-------------------|------------------|----------------|-----------------|
| **1** | <10 заявок или <2% исполнения | **2** | 1 | 1 |
| **2** | <200 заявок, >10% | **4** | 1 | 1 |
| **3** | <1000 заявок, >10% | **5** | 1 | 1 |
| **4** | <5000 заявок, >10% | **16** | 1 | 1 |
| **5** | >5000 заявок, >50% | **∞ (без лимита)** | 1 | 1 |

**Важно:**
- Грейды обновляются **раз в сутки** после окончания торгов [[5]]
- Счетчик stream-соединений обновляется каждые **2 минуты** [[5]]
- Для повышения грейда нужно выставить **минимум 1 заявку в месяц** [[5]]

### **4.3. Лимиты внутри стрим-соединения**

В **одном** stream-соединении котировок:
- **300 подписок** суммарно на свечи + стаканы + сделки [[5]]
- **Без ограничений** на подписки Info (статусы) [[5]]

**Пример распределения для 50 инструментов:**
- 50 подписок на свечи
- 50 подписок на стаканы
- 50 подписок на сделки
- Итого: 150 подписок (в пределах лимита 300)

## 5. 🔧 Специальные типы данных

### **MoneyValue** — Денежная сумма с валютой
```protobuf
{
    currency: "rub",      // ISO-код валюты
    units: 150,           // целая часть
    nano: 500000000       // дробная часть (9 знаков после запятой)
}
// = 150.50 RUB
```

### **Quotation** — Котировка (без валюты)
```protobuf
{
    units: 150,
    nano: 500000000
}
// = 150.50
```

**Преобразование:**
```java
// Java пример
BigDecimal value = BigDecimal.valueOf(moneyValue.getUnits())
    .add(BigDecimal.valueOf(moneyValue.getNano(), 9));
```

## 7. 🚨 Обработка ошибок

### **Заголовки для rate limiting:**
- `x-ratelimit-limit` — текущий лимит по методу [[2]]
- `x-ratelimit-remaining` — оставшиеся запросы [[2]]
- `x-ratelimit-reset` — время до обнуления счетчика (секунды) [[2]]
- `x-tracking-id` — UUID запроса для техподдержки [[2]]

### **Ключевые коды ошибок:**

| Код | Тип | Описание | Действие |
|-----|-----|----------|----------|
| **40003** | UNAUTHENTICATED | Невалидный/отсутствует токен | Перевыпустить токен |
| **30034** | RESOURCE_EXHAUSTED | Превышен лимит запросов | Увеличить интервал между запросами |
| **80001** | RESOURCE_EXHAUSTED | Превышен лимит stream-соединений | Закрыть лишние стримы |
| **40001** | INVALID_ARGUMENT | Некорректные параметры запроса | Проверить параметры |
| **40002** | NOT_FOUND | Инструмент/ордер не найден | Проверить ID |
| **50001** | INTERNAL | Внутренняя ошибка сервера | Retry с backoff |
| **50003** | UNAVAILABLE | Сервис временно недоступен | Retry с backoff |

## 9. 💡 Рекомендации для скальпинг-системы

### **9.1. Оптимизация latency:**

1. **Использовать gRPC стримы**, а не REST polling
2. **WebSocket proxy** если нужен JSON (но gRPC быстрее)
3. **Предварительная подписка** на все инструменты при старте
4. **Keep-alive** соединения (Ping каждые 30 сек)
5. **Локальный кэш** инструментов и их метаданных

### **9.2. Обработка лимитов:**

```java
// Пример расчета лимитов для 50 инструментов
int instruments = 50;
int streamsNeeded = (int) Math.ceil((double) instruments * 3 / 300); // свечи + стаканы + сделки
// = 1 stream соединение

// Требуемый грейд: минимум 1 (2 stream соединения)
// Рекомендуется грейд 2+ (4 stream соединения) для надежности
```

### **9.3. Идемпотентность ордеров:**

```java
// Всегда передавать уникальный order_id
String orderId = UUID.randomUUID().toString();
PostOrderRequest request = PostOrderRequest.newBuilder()
    .setOrderId(orderId)  // предотвращает дубликаты
    .setInstrumentId(figi)
    .setQuantity(10)
    .setDirection(OrderDirection.ORDER_DIRECTION_BUY)
    .setOrderType(OrderType.ORDER_TYPE_LIMIT)
    .setPrice(price)
    .build();
```

### **9.4. Мониторинг торговых статусов:**

```java
// Проверка перед выставлением ордера
if (tradingStatus != SecurityTradingStatus.SECURITY_TRADING_STATUS_NORMAL_TRADING) {
    log.warn("Trading not available for {}", figi);
    return;  // не торговать
}
```

### **9.5. Обработка отключений:**

```java
// Автоматическое переподключение стримов
private void reconnectStream() {
    int retryCount = 0;
    while (retryCount < MAX_RETRIES) {
        try {
            stream = createNewStream();
            resubscribeAllInstruments();
            return;
        } catch (Exception e) {
            retryCount++;
            Thread.sleep(1000 * retryCount);  // exponential backoff
        }
    }
}
```

### **9.6. Расчет реальной цены ордера:**

```java
// Важно: quantity в PostOrderRequest — это количество ЛОТОВ, не штук!
int lotSize = instrument.getLot();  // например, 10 для SBER
int totalShares = quantity * lotSize;
BigDecimal orderPrice = BigDecimal.valueOf(price.getUnits())
    .add(BigDecimal.valueOf(price.getNano(), 9));
BigDecimal totalCost = orderPrice.multiply(BigDecimal.valueOf(totalShares));
```

## 11. 🎯 Итоговые рекомендации для вашей системы

### **Для Java Data Collector:**
1. Использовать **MarketDataStreamService** для получения свечей и стаканов
2. Подписаться на **Info** для отслеживания торговых статусов
3. Буферизировать данные перед отправкой в Kafka
4. Обрабатывать переподключения при потере связи

### **Для Python Analyzer:**
1. Получать данные из Kafka (не напрямую из API)
2. Использовать только **Unary-методы** для получения исторических данных при необходимости
3. Хранить метаданные инструментов в локальном кэше

### **Для Java Trader:**
1. Использовать **PostOrder** для открытия позиций
2. Сразу выставлять **StopOrders** (stop-loss + take-profit)
3. Подписаться на **TradesStream** для отслеживания исполнения
4. Использовать **ReplaceOrder** для модификации заявок
5. Всегда проверять **trading_status** перед торговлей

### **Для повышения грейда:**
- Выставлять минимум **200+ заявок в месяц** с **>10% исполнением**
- Это даст **грейд 2+** с 4 stream-соединениями котировок
- Для больших портфелей (50+ инструментов) стремиться к грейду 4+ (16 стримов)
